## 节点语法

### 节点类型一览

| 写法 | 形状 | 用在哪 |
|-----|------|-------|
| `A[文字]` | 方框 | 通用节点 |
| `A(文字)` | 圆角框 | 开始/结束 |
| `A([文字])` | 体育场形 | 起点/终点 |
| `A((文字))` | 圆形 | 重点标注、中心 |
| `A{文字}` | 菱形 | 判断/决策 |
| `A{{文字}}` | 六边形 | 特殊处理 |
| `A[/文字/]` | 平行四边形 | 输入/输出 |
| `A[(文字)]` | 数据库形 | 存数据的地方 |
| `A[[文字]]` | 子程序 | 调用外部 |
| `A>文字]` | 不对称箭头 | 特殊用途 |

### 节点文字规则

**换行：**
- `<br/>` 只在圆形节点有效：`((第一行<br/>第二行))`
- 其他节点保持文字简洁，太长就拆多个节点

**特殊字符：**
- 空格：用引号 `["带空格的文字"]`
- 引号：用 `『』` 替代英文引号
- 括号：用 `「」` 替代英文括号
- 冒号：通常安全，但有问题就避开
- 连字符：安全可用

**长度建议：**
- 节点文字控制在 50 字符内
- 太长就用圆节点换行，或拆成多个节点

## 子图语法

### 基本结构

```
graph TB
    subgraph id["显示名称"]
        direction TB
        A --> B
    end

    subgraph simple
        C --> D
    end

    subgraph horiz["水平排列"]
        direction LR
        E --> F
    end
```

### 嵌套子图

```
graph TB
    subgraph outer["外层"]
        direction TB

        subgraph inner1["内层1"]
            A --> B
        end

        subgraph inner2["内层2"]
            C --> D
        end

        inner1 -.-> inner2
    end
```

**限制：** 嵌套最多 2 层，再多就乱了。

### 连接子图（区分场景）

**流程图/对比图/思维导图（默认）：**
```
graph TB
    subgraph g1["组1"]
        A[节点A]
    end

    subgraph g2["组2"]
        B[节点B]
    end

    A --> B          ✅ 连接具体节点（推荐）
    g1 -.-> g2       ✅ 连接子图（用于布局）
```

**架构图（⚠️ 特殊规则）：**
```
graph TB
    subgraph FE["前端层"]
        Client[客户端]
    end

    subgraph GW["网关层"]
        API[API网关]
    end

    FE --> GW        ✅ 必须使用子图ID连接层级
    Client --> API   ❌ 严禁使用内层节点ID连接
```

> ⚠️ **架构图强制规则**：层级之间的连线**必须使用子图ID**（如 `FE --> GW`），**绝对禁止**使用内部实体节点ID（如 `Client --> API`）。这是为了保持分层架构的抽象语义，避免图画成"组件调用图"。完整规则详见 [architecture-diagram.md](architecture-diagram.md)

**场景对照表：**

| 图表类型 | 推荐方式 | 说明 |
|---------|---------|-----|
| 流程图 | 节点连接 `A --> B` | 展示具体步骤的流转 |
| 对比图 | 节点连接 `A1 --> A2` | 展示分支内部结构 |
| 思维导图 | 节点连接 | 展示层级主题关系 |
| **架构图** | **子图ID连接 `FE --> GW`** | **强制：层与层之间的抽象连接** |

## 箭头与连线

### 基本箭头

| 写法 | 线型 | 用在哪 |
|-----|------|-------|
| `A --> B` | 实线箭头 | 正常流程 |
| `A -.-> B` | 虚线箭头 | 可选/辅助 |
| `A ==> B` | 粗线箭头 | 强调/重要 |
| `A --- B` | 实线无箭头 | 关联/并列 |
| `A ~~~ B` | 不可见连线 | 布局占位 |
| `A <--> B` | 双向实线 | 双向关系 |
| `A <-.-> B` | 双向虚线 | 双向可选 |

### 加标签

```
A -->|标签文字| B
A -.->|可选路径| B
A ==>|重要路径| B
```

### 多目标连接

```
A --> B --> C --> D        # 一连到底
A --> B & C & D            # 一分多支
A & B --> C                # 多合一
```

## 样式与颜色

### 单节点样式

```
style A fill:#d3f9d8,stroke:#2f9e44,stroke-width:2px
```

### 批量样式

```
style A,B,C fill:#d3f9d8,stroke:#2f9e44,stroke-width:2px
```

### 颜色格式

- 十六进制：`#ff0000` 或 `#f00`
- RGB：`rgb(255,0,0)`（部分平台支持）
- 颜色名：`red`、`blue` 等（支持有限）

### 专业色板

| 语义 | 填充色 | 边框色 | 用在哪 |
|------|--------|--------|-------|
| 输入/开始 | `#d3f9d8` | `#2f9e44` | 开始、输入、感知 |
| 关键/决策 | `#ffe3e3` | `#c92a2a` | 结束、错误、关键点 |
| 处理/逻辑 | `#e5dbff` | `#5f3dc4` | 处理、计算、推理 |
| 动作/执行 | `#ffe8cc` | `#d9480f` | 动作、操作、执行 |
| 输出/结果 | `#c5f6fa` | `#0c8599` | 输出、执行结果 |
| 数据/存储 | `#fff4e6` | `#e67700` | 存储、记忆、数据 |
| 学习/优化 | `#f3d9fa` | `#862e9c` | 学习、优化、改进 |
| 元数据/标题 | `#e7f5ff` | `#1971c2` | 定义、标题、元信息 |
| 次要/辅助 | `#f8f9fa` | `#868e96` | 可选、次要、传统系统 |

**配色原则：** 浅色填充 + 深色边框，对比度才够。

## 布局与方向

### 方向代码

| 写法 | 方向 | 适用场景 |
|-----|------|---------|
| `graph TB` | 上到下（默认） | 顺序流程、层级结构 |
| `graph BT` | 下到上 | 反向流程 |
| `graph LR` | 左到右 | 时间线、宽屏展示 |
| `graph RL` | 右到左 | 特殊布局 |
| `graph TD` | 上到下 | 同 TB |

### 子图内单独设置方向

```
graph TB
    subgraph vertical["垂直流程"]
        direction TB
        A --> B --> C
    end

    subgraph horizontal["水平流程"]
        direction LR
        D --> E --> F
    end
```

## 高级布局模式

### 泳道模式（分组）

```
graph TB
    subgraph lane1["泳道1"]
        A[步骤1] --> B[步骤2]
    end

    subgraph lane2["泳道2"]
        C[步骤3] --> D[步骤4]
    end

    B --> C
```

### 反馈循环模式

```
graph TB
    A[开始] --> B[处理]
    B --> C[输出]
    C -.->|反馈| A

    style A fill:#d3f9d8,stroke:#2f9e44,stroke-width:2px
    style B fill:#e5dbff,stroke:#5f3dc4,stroke-width:2px
    style C fill:#c5f6fa,stroke:#0c8599,stroke-width:2px
```

### 中心辐射模式

```
graph TB
    Hub[中心节点]

    A[分支1] --> Hub
    B[分支2] --> Hub
    C[分支3] --> Hub
    Hub --> D[输出]
```

### 决策树模式

```
graph TB
    Start[开始] --> Decision{判断?}
    Decision -->|选项A| PathA[路径A]
    Decision -->|选项B| PathB[路径B]
    Decision -->|选项C| PathC[路径C]

    PathA --> End[结束]
    PathB --> End
    PathC --> End
```

### 对比布局模式

```
graph TB
    Title[对比]

    subgraph left["方案 A"]
        A1[特点1]
        A2[特点2]
        A3[特点3]
    end

    subgraph right["方案 B"]
        B1[特点1]
        B2[特点2]
        B3[特点3]
    end

    Title --> left
    Title --> right

    subgraph compare["关键差异"]
        Diff[差异总结]
    end

    left --> compare
    right --> compare
```

## 节点合并原则

**核心原则：同类节点合并，避免过度细化。**

流程图变复杂的根本原因是**节点过多、分支过细**，而不是某个特定类型的节点有问题。

### 问题示例

❌ **同类节点过度拆分：**
```
graph TB
    %% 错误分支过度细化
    check --> err1[ARTICLE_OWNERSHIP_CONFLICT]
    check --> err2[CATEGORY_REQUIRED]
    check --> err3[COLUMN_REQUIRED]
    check --> err4[COLUMN_NOT_FOUND]

    %% 主流程也可以过度细化
    process1[解析封面] --> process2[正文首图回退] --> process3[生成缩略图]
```
- 4个错误节点本质都是"参数校验失败"
- 3个处理步骤可以合并为"处理封面"

### 推荐做法

✅ **同类节点合并：**
```
graph TB
    check{参数校验} -->|通过| process[处理封面]
    check -->|失败| error[参数校验失败]
```

✅ **或用列表展示细节：**
```
graph TB
    error["参数校验失败<br/>- 分类ID与专栏ID冲突<br/>- 分类必填<br/>- 专栏不存在"]
```

### 合并规则

| 场景 | 处理方式 | 示例 |
|------|---------|------|
| 多个同类校验错误 | 合并为一个错误节点 | 4种校验错误 → 1个"参数校验失败" |
| 连续的同类处理步骤 | 合并为一个处理节点 | 解析封面→首图回退→生成缩略图 → "处理封面" |
| 多个平行的子模块 | 用子图归类 | 4个输入字段 → 放入"输入信息"子图 |
| 核心业务节点 | 可以单独展示 | 支付成功/失败是核心，可分开 |

**口诀：同类合并，突出重点，避免枚举。**
