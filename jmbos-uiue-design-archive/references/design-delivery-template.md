# 设计交付物标准模板

> 本模板定义迭代工作区和知识图谱中设计产物的标准格式规范。

---

## 一、HTML页面模板

### 1.1 文件头元信息（必须）

每个归档的 HTML 文件**必须**在 `<head>` 内的第一行包含以下注释：

```html
<!--
  ============================================================
  JMBOS UI/UE 设计产物
  ============================================================
  产物编号: D-{序号}
  页面名称: {中文名称}
  页面类型: 列表页 | 表单页 | 详情页 | 弹窗 | 抽屉 | 其他
  所属模块: {功能模块名称}
  路由ID: {kebab-case路由ID，与 window.__pageId 一致}
  需求来源: {PRD编号} / {UC编号}
  所属迭代: {YYYYMMDD-迭代名称}
  最后更新: YYYY-MM-DD
  ============================================================
-->
```

#### 唯一入口（index.html）专用元信息头

`index.html` 无 D-编号，使用以下专用元信息头：

```html
<!--
  ============================================================
  JMBOS UI/UE 设计产物 - 唯一入口
  ============================================================
  产物编号: INDEX
  页面名称: 唯一入口
  页面类型: 唯一入口
  所属模块: 全局
  需求来源: {PRD编号} / {UC编号}
  所属迭代: {YYYYMMDD-迭代名称}
  最后更新: YYYY-MM-DD
  包含页面: D-001, D-002, D-005（列出所有聚合的子页面编号）
  ============================================================
-->
```

### 1.2 元信息字段说明

| 字段 | 必填 | 说明 | 示例 |
|------|------|------|------|
| `产物编号` | **是** | 唯一标识，格式 D-XXX，HTML 与配套 JS 同编号同名 | `D-001` |
| `页面名称` | **是** | 简洁的中文描述 | `用户列表页` |
| `页面类型` | **是** | 页面布局类型 | `列表页` |
| `所属模块` | **是** | 归属的功能模块，归档分目录依据 | `用户管理` |
| `路由ID` | **是** | kebab-case 内部路由ID，与页面 `window.__pageId` 及 `common.js` 的 `pageRoute` key 一致；对用户不可见；`index.html` 无此字段 | `user-list` |
| `需求来源` | 推荐 | 关联的需求文档编号 | `PRD-20260101-001` |
| `所属迭代` | **是** | 来源迭代名称 | `20260101-用户管理优化` |
| `最后更新` | **是** | 产物最后一次修改日期（归档为直接覆盖策略，无版本递增） | `2026-01-15` |
| `包含页面` | 唯一入口必填 | 聚合的所有子页面编号列表 | `D-001, D-002, D-005` |

### 1.3 完整示例（MPA 四部分结构）

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <!--
    ============================================================
    JMBOS UI/UE 设计产物
    ============================================================
    产物编号: D-001
    页面名称: 用户列表页
    页面类型: 列表页
    所属模块: 用户管理
    路由ID: user-list
    需求来源: PRD-20260101-001 / UC-USER-LIST-001
    所属迭代: 20260101-用户管理功能优化
    最后更新: 2026-01-15
    ============================================================
  -->
  <title>用户列表 - JMBOS</title>
  <link rel="stylesheet" href="../css/common.css">
  <style>
    /* 页面专用样式（Design Tokens 变量定义于 css/common.css，此处仅页面级样式） */
  </style>
</head>
<body>
  <!-- 页面内容（#header / #sidebar 挂载点 + .main-wrapper 内容区） -->
  ...

  <!-- 配套JS引用：__pageId 声明 + 公共JS + 配套JS -->
  <script>window.__pageId='user-list';</script>
  <script src="../js/common.js"></script>
  <script src="../js/pages/D-001_用户列表.js"></script>
</body>
</html>
```

> **配套 JS**：`js/pages/D-001_用户列表.js` 与 HTML 同编号同名，仅含函数定义 + IIFE 初始化。

## 三、素材资源命名规范

### 3.1 截图类

```
screenshot-{页面编号}-{用途}.{ext}
```

| 用途后缀 | 说明 |
|---------|------|
| `_full` | 整页截图 |
| `_desktop` | 桌面端视图 |
| `_mobile` | 移动端视图（如有） |
| `_detail` | 局部细节放大 |

**示例**：
```
screenshot-D001-full.png
screenshot-D001-detail_查询栏.png
```

### 3.2 图标类

```
icon-{名称}-{尺寸}px.{ext}
```

**示例**：
```
icon-search-16px.svg
icon-user-avatar-40px.png
```

### 3.3 导出资源类

```
export-{组件名}-{来源工具}.{ext}
```

**示例**：
```
export-primary-button-figma.svg
export-table-header-sketch.png
```

## 四、质量检查清单

归档前对每个产物进行以下检查：

### HTML页面检查项

| # | 检查项 | 通过标准 |
|---|--------|---------|
| H1 | 元信息完整 | 包含全部必填字段（产物编号/页面名称/页面类型/所属模块/路由ID/需求来源/所属迭代/最后更新） |
| H2 | 可独立打开 | `index.html` 引用的 `css/common.css`、`js/common.js`、各页面 `.html` 引用的 `../js/common.js`、`../js/pages/D-XXX_{页面功能名称}.js` 路径正确且文件存在 |
| H3 | 编码正确 | UTF-8，无乱码 |
| H4 | Design Tokens 完整 | `css/common.css` 包含完整 CSS 变量定义；页面 `.html` 内联 `<style>` 中的样式使用 CSS 变量引用 |
| H5 | 图标库完整 | `js/common.js` 已内联完整 icons-sprite.svg（113个全部） |
| H6 | Logo 规范 | 使用 CSS 变量，无硬编码品牌色 |
| H7 | 资源引用路径有效 | `index.html` 的 `css/common.css`、`js/common.js` 路径正确（根目录同级，无需修正）；`js/common.js` 中 `pageRoute` 的 `pages/D-XXX_{页面功能名称}.html` 路径正确 |
| H8 | 菜单数据完整 | 菜单基于 §3.8 菜单归属矩阵生成，无跨一级模块菜单混入 |
| H9 | 路由ID一致 | 每个子页面 `.html` 声明 `window.__pageId`，且与元信息头"路由ID"、`js/common.js` 的 `pageRoute` key 三者一致 |

### 文档检查项

| # | 检查项 | 通过标准 |
|---|--------|---------|
| D1 | 格式规范 | Markdown 格式正确 |
| D2 | 信息完整 | 包含基本信息表 |
| D3 | 引用准确 | 编号、路径可追溯 |

### 图片检查项

| # | 检查项 | 通过标准 |
|---|--------|---------|
| I1 | 文件可读 | 非0字节，可正常打开 |
| I2 | 命名规范 | 符合命名规则 |
| I3 | 格式合适 | PNG用于截图，SVG用于矢量图形 |
