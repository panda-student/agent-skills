# 并行协调工作流 — 主/子代理分工与模板（填充/改造双模式）

> **定位**：本文件是 [SKILL.md §6.8 并行协调](../SKILL.md) 的**分工手册与产物模板**。§一 模式选择；§二 主代理工作流（2A 填充型 / 2B 改造型）；§三 子代理工作流（3.1 填充型 / 3.2 改造型）；附录 A-E 为对应产物模板。
>
> **关键约定**：子代理**不读取本文件**，也无 SKILL.md 上下文——其全部指令由主代理按附录 B/D 模板编译后注入。
>
> * 索引入口 → [SKILL.md](../SKILL.md)

## 一、分工总览与模式选择

### 1.1 模式选择（主代理判定，结果记入 G9 追踪表）

| 任务情形 | 处理 |
| --- | --- |
| 全新页面多模块并行生成 | **模式A 并行填充**（§2A + §3.1 + 附录A/B/C） |
| 修改类多文件任务（原型改造/样式改造/清洗/批量修正）且满足三前提 | **模式B 并行改造**（§2B + §3.2 + 附录D/E） |
| 修改类任务但任一前提不满足｜单文件改造｜深度拆分（M1/M11）｜涉及公共文件 | **串行原地修改，禁止并行** |

**模式B 三前提（缺一不可）**：
- **P1 单元独立**：并行单元 = 独立文件，一文件 = 一子代理，无同文件双写
- **P2 规则可注入**：改造规则已固化为《改造配方卡》（附录E），子代理零规范阅读
- **P3 试点先行**：首个文件由主代理串行改造且脚本校验全 PASS，配方锁定后方可派发

**同页面/同文件规则（两模式通用硬边界）**：
- **同文件写入权唯一**：任何时刻一个文件只允许一个执行者（主代理或唯一子代理），禁止两个执行者同时写同一文件——直接双写会互相覆盖导致内容失效/丢失
- **同页面多模块并行仅限模式A片段返回制**：子代理只返回文本片段，写入全部由主代理串行合并（M5+合并清点）；任何模式下子代理直接编辑页面文件即违规
- 同文件多模块的**修改**（无独立文件边界）→ 一律串行，交主代理原地完成

### 1.2 分工总览

| 环节 | 执行者 | 动作 | 依据/模板 |
| --- | --- | --- | --- |
| ①A 契约产出 | 主代理（串行） | 读规范 → 抽取关键样式值 → 填写契约 | 附录 A |
| ①A 骨架搭建 | 主代理（串行） | Grep 提取骨架段写入各页面文件 | G1.1 四部分组织 |
| ②A 并行填充 | 子代理 ×N（填充型） | 各领 1 份契约裁剪指令 + 1 个容器ID，纯填充 | §3.1 + 附录 B |
| ②A 合并写入 | 主代理（串行） | 收取子代理产物并写入文件 | — |
| ③A 整合校验 | 主代理（串行） | C1-C5 校验 → 修正重验 → 全 PASS | 附录 C |
| ①B 规则固化 | 主代理（串行） | 抽取改造规则 → 产出配方卡 | 附录 E |
| ①B 试点改造 | 主代理（串行） | 改造首个文件 → 脚本全 PASS → 锁定配方 | §2B R2 |
| ②B 并行改造 | 子代理 ×N（改造型） | 各领 1 个目标文件 + 配方卡，原地局部修改+自检 | §3.2 + 附录 D |
| ②B 验收复检 | 主代理（串行） | 批量脚本复检 + §7.6 内容完整性抽验 | §2B R6 |

> 为什么必须有护栏：并行子代理上下文独立，若各自读规范/模板会 token 成倍放大，且易走样为"从零重写"（违反 G11）。**契约/配方卡的作用是主代理串行阶段一次性锁定规则与样式值，子代理只做受控的"填充"或"按配方替换"**。无护栏的并行一律禁止。

## 二、主代理工作流（串行编排方）

### 2A 模式A·并行填充（全新页面）

> 执行时机：SKILL.md §5 方案确认（QG5）通过后、进入 §6.8 时。

#### M1 前置确认

确认满足全部前置：①场景路由=并行生成（全新页面）②QG5 已通过 ③《需求完整清单》《组件完整清单》已产出。

#### M2 产出《布局契约文档》

按附录 A 模板逐节填写：

1. 从 §6.2《关键样式值抽取清单》与组件规范摘抄各模块关键样式值，填入契约 A.5 规范注入区（**填得越全，子代理越不需要读规范文件**）
2. 划分模块并分配容器 ID 与模块前缀（契约 A.3，一行 = 一个子代理任务）
3. 契约产出后向用户呈现（可并入 §5 确认材料补确认），通过后方可进入 M3

#### M3 搭建骨架（并行发起前完成）

1. 按 G1.1 从 `ASSETS/page-shells/pages/{list|detail|form|modal}.html` 用 Grep 提取骨架段，写入 `2.UI/tmp/pages/D-XXX_{名称}.html`（含 `#header`/`#sidebar` 挂载点、`.main-wrapper`、`#page-content`、`.page-card` 及各空模块容器）
2. 写入元信息头、`window.__pageId`、common 引用（G1.1 第0/3部分）
3. ⚠️ 只读目标页面类型的模板，单模板 45KB+，禁止一次读全部 4 个

#### M4 编译子代理指令并并行发起

1. 按附录 B 模板，从契约裁剪生成每个子代理的**自包含指令**（输入+规范注入+铁律+产出要求）
2. 调度规则：
   - 子代理数量 = 模块数（契约 A.3 行数），**单消息并行发起**
   - 弹窗/抽屉不单独开子代理：为嵌入式组件（依 G1），由所属页面的模块任务一并产出片段
   - 指令中**只允许引用契约规范注入区内容**，不允许引用规范文件路径令子代理自行阅读

#### M5 合并写入

子代理返回产物后，由**主代理**（而非子代理）负责写入目标文件：HTML 片段插入对应容器ID、`<style>` 追加到 `<head>`、JS 增量写入 `js/pages/D-XXX_{页面功能名称}.js`（依 G1.2）。

**合并清点（写入后立即执行，防片段丢失）**：按契约 A.3 逐行核对——①每个容器ID内内容非空且与所派模块一致 ②各模块 `<style>` 增量均已并入且无重复定义 ③JS 增量均并入配套文件且函数名无冲突。任一缺项 → 向对应子代理产物补录（无产物则重派该模块），禁止带缺项进入 M6。

#### M6 整合校验

按附录 C 执行 C1-C5 校验并输出记录：任一 FAIL → 修正 → 重验 → 全 PASS 后方可进入 §7 自检。通过后按 G10 输出步骤6完成证明。

### 2B 模式B·并行改造（修改场景：原型改造/样式改造/清洗/批量修正）

> 执行时机：意图识别为原地改造（§1.1）、目标文件 ≥2 个且三前提全满足时启用；否则按原流程逐页串行。

#### R1 规则固化（先于一切并行动作）

从权威来源抽取本次改造规则，按附录 E 填写《改造配方卡》。来源映射：

| 改造类型 | 规则来源 |
| --- | --- |
| 值级清洗（颜色/圆角/间距变量化） | [external-html-workflow.md §2.2 污染映射表](external-html-workflow.md) + §7.0 脚本映射 |
| 结构合规纠正 | external §1.3 M1-M14 检测项表（M5/M6/M10 类骨架项属深度纠正，见"禁止并行"） |
| 样式改造（某组件样式变更） | 对应组件规范文件 + style-fix-cheatsheet S编号条目 |
| 批量修正（脚本 FAIL 项修复） | §7.0 quick-fix 映射；无脚本的项列入手动配方 |

#### R2 试点先行（配方锁定关卡）

1. 主代理**串行**改造 1 个目标文件（选典型复杂度），跑配方指定校验脚本至全 PASS
2. 将试点中发现的坑点写回配方卡"试点验证"栏（如替换顺序、易误判场景）
3. 配方未锁定（试点未全 PASS）**禁止派发任何子代理**

#### R3 任务划分

1. 列出全部目标文件，**一文件 = 一子代理任务**；弹窗/抽屉片段跟随所属页面文件，不单列
2. 剔除必须串行的项（交主代理处理）：
   - **公共文件**：`css/common.css`、`js/common.js`、`icons-sprite.svg`、`索引.md`、导航菜单数据
   - **深度拆分类**：M1/M11 SPA→MPA、flatten 三部分分离（输出文件由单一源文件派生，须统一编排）
   - **同文件多模块改造**：无独立文件边界，并行双写冲突

#### R4 编译指令并并行发起

按附录 D 模板编译每个子代理指令（目标文件路径 + 配方卡 + 搬运铁律 + 自检命令），**单消息并行发起**。指令必须自包含，禁止让子代理自行读规范/外部文档。

#### R5 并行执行（子代理侧，见 §3.2）

子代理原地局部修改各自文件并自跑脚本自检，返回证据包。

#### R6 验收复检

1. 主代理对**全部**目标文件批量复检：`validate-design.mjs` + `style-scan.mjs` + `structure-fix.mjs --detect`（按改造类型取用），不信任子代理自检结论、只信脚本输出
2. 按 §7.6 抽验内容完整性：输出与源文件 DOM/文案一一对应，体积守恒 ±15%（依 G2.1）
3. FAIL 项由主代理修正重验 → 全 PASS 后进入 §7 自检，按 G10 输出步骤6完成证明

## 三、子代理工作流（受控执行方）

> ⚠️ 子代理不读取本文件与 SKILL.md——本节定义其职责边界，是主代理 M4/R4 编译指令的内容来源；实际指令按附录 B/D 注入。

### 3.1 填充型子代理（模式A）

**输入（主代理已就绪，直接使用，不自行获取）**

| 输入项 | 来源 |
| --- | --- |
| 目标文件路径 | M3 已写入骨架的 `2.UI/tmp/pages/D-XXX_{名称}.html` |
| 分配容器 ID | 契约 A.3（已存在于 .page-card 内） |
| 模块前缀 | 契约 A.3（所有 CSS 选择器以此开头） |
| 规范注入 | 契约 A.5 对应模块块（**唯一取值来源**） |
| 交互编号 | 契约分配的 IX 编号 |

**执行步骤**

1. **S1 生成 HTML**：按规范注入的结构要点，产出容器内 HTML 片段（内容与组件结构从注入区取值）
2. **S2 生成 CSS**：以模块前缀开头的选择器 + CSS 变量（design-tokens 值见注入区），产出追加到 `<head>` 的 `<style>` 块内容
3. **S3 生成 JS**：按 IX 编号实现交互（函数定义 + IIFE 初始化，依 G1.2），产出配套 JS 增量
4. **S4 返回产物**：仅返回三段产物，不做其他动作

**铁律（八条，主代理原样注入指令）**

1. 禁止改骨架：产出片段的范围仅限分配的容器 ID 内部，不新增/删除/移动容器树节点
2. 禁止自定义卡片样式：不写 background-color/border-radius/box-shadow 到模块容器
3. 仅产出指定容器 ID 的片段：越界内容即 FAIL
4. CSS 选择器以模块前缀开头
5. 样式值用 CSS 变量，禁止硬编码
6. 内容从规范注入区取值，**禁止自行阅读组件规范/页面模板**（防止 token 放大与走样）
7. 交互逻辑按分配的 IX 编号实现，产出配套 JS 增量（G1.2）
8. **禁止直接编辑/写入任何文件**（含目标文件）：本任务只产出文本片段，文件写入由主代理统一执行（M5）——同文件多代理直接写入会互相覆盖导致内容丢失

**产出要求**

1. 仅返回：①容器内 HTML 片段 ②`<head>` 追加的 `<style>` 块内容 ③配套 JS 增量
2. 禁止输出容器树改动、禁止输出其他模块内容、禁止改写公共文件（common.css/common.js）
3. **禁止执行任何文件写入/编辑操作**——违反即整包作废，由主代理重派

### 3.2 改造型子代理（模式B）

**输入（主代理已就绪，直接使用，不自行获取）**

| 输入项 | 来源 |
| --- | --- |
| 目标文件路径 | R3 分配的**唯一**目标文件（原文件即基底） |
| 改造配方 | 附录 E 配方卡（**唯一执行依据**） |
| 自检命令 | 配方卡指定（如 `node scripts/validate-design.mjs <文件>`） |

**执行步骤**

1. **T1 读取目标文件**：仅读取分配的文件，禁止读取规范/模板/其他文件
2. **T2 按配方执行**：逐处局部替换/纠正（Edit 局部修改），**禁止整文件重写**
3. **T3 自跑校验**：执行配方指定脚本至 PASS；两次修正仍 FAIL → 原样返回失败项，**禁止虚报 PASS**
4. **T4 返回证据包**：修改摘要 + 脚本证据 + 体积对比

**搬运铁律（七条，主代理原样注入指令）**

1. 原文件为基底原地修改，禁止删除重建/另起文件/从零重写（G11）
2. 内容搬运：DOM 结构与业务文案必须与源文件一一对应，禁止凭记忆或规范重写
3. 体积守恒：改造前后行数/字符数 ±15% 内（依 G2.1），大幅缩减 = 误删或重写
4. 仅按配方执行替换与纠正，禁止配方外的"顺手优化"
5. 禁止触碰公共文件（common.css/common.js/icons-sprite/索引/导航数据）
6. 仅修改分配的目标文件，禁止越文件操作
7. 校验 FAIL 不得虚报，原样返回失败项原文

**产出要求（证据包）**

1. 修改摘要：替换/纠正项计数与位置
2. 脚本证据：自检命令 + 输出结果行（PASS 原文）
3. 体积对比：修改前后行数/字符数（守恒 ±15%）

### A.2 全局容器树（所有页面一致，禁止子代理改动）

```markdown
#header                      → 顶导（42px，代码见 nav-menu-full-code.md）
└─ #sidebar.sidebar          → 侧边栏（180px，仅当前模块菜单，依 G5）

   └─ main.main-content
      └─ #page-content
```

**骨架来源**：`ASSETS/page-shells/pages/{list|detail|form|modal}.html`（M3 由主代理 Grep 提取骨架段，子代理禁止再读模板文件）。

### A.3 模块划分与容器分配表

> 一行 = 一个并行填充单元 = 一个子代理任务。容器 ID 一旦分配不可变更。

| 序号 | 模块名称 | 容器ID（页面内唯一） | 所在页面/文件 | 页面类型 | 模块前缀 | 需用组件（规范文件） | 模块容器约束 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | {如 查询筛选区} | `#mod-{功能}-filter` | pages/D-001_{名称}.html | 列表页 | `.m-{功能}-filter` | query-bar.md | 禁自带 bg/radius/shadow |
| 2 | {如 数据表格区} | `#mod-{功能}-table` | 同上 | 列表页 | `.m-{功能}-table` | tables.md + tags.md + action-buttons.md | 同上 |
| 3 | {如 分页区} | `#mod-{功能}-pager` | 同上 | 列表页 | `.m-{功能}-pager` | pagination.md | 同上 |

**统一容器约束**：模块容器不得自带 `background-color` / `border-radius` / `box-shadow`（卡片样式权归 `.page-card`/`.card` 两层，依 S47-S50）。

### A.4 CSS 命名空间约定

| 项 | 约定 |
| --- | --- |
| 选择器前缀 | 所有 CSS 选择器必须以 A.3 分配的模块前缀开头（如 `.m-{功能}-table .jm-btn{...}`），防跨模块污染 |
| 样式值 | 一律使用 CSS 变量（来源 `design-tokens.css`，如 `var(--color-primary)`），禁止硬编码 |
| 新增变量 | 禁止。契约未包含的值一律从 design-tokens.css 取 |
| 样式写入位置 | 页面 `<head>` 的 `<style>` 块内（G1.1 四部分组织），禁止内联 `style="..."` |
| 业务JS | 写入 `js/pages/D-XXX_{页面功能名称}.js`（函数定义 + IIFE 初始化，依 G1.2），禁止内联到 HTML |

### A.5 规范注入区（子代理免读规范的唯一数据源）

> 主代理 M2 从 §6.2《关键样式值抽取清单》与组件规范摘抄，逐模块填入。

```markdown
【模块 2：{数据表格区}】规范注入
- 组件：表格 tables / 标签 tags / 操作列 action-buttons
- 关键样式值：{...}
- 结构要点：{...}
- 禁止项：{...}
```

## 附录B 填充型子代理指令模板（模式A）

> 主代理 M4 每个子代理编译一份，从契约裁剪生成；指令必须自包含（子代理无 SKILL.md 上下文）。

