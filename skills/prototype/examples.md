# prototype 技能示例

## 例：逻辑分支——草稿冲突合并策略

- 问题："多标签页同时编辑时，草稿以最后一次输入为准，还是按时间戳逐字段合并？"
- 产出：单 HTML。顶部写问题；状态面板显示两份草稿内容与时间戳；按钮模拟 A/B 标签交替输入；一键回放"快速交替输入""离线后恢复""同一字段同时改"三种冲突序列
- 归档：`prototype/draft-conflict-merge.html` 提交到 `prototype/draft-conflict-merge` 分支
- 结论去处：实现 issue 写"按时间戳逐字段合并，因为回放显示最后写入制会丢 A 的独立修改"，附分支指针

## 例：UI 分支——任务中心首页信息架构

- 问题："巡检任务中心首页，指标优先还是任务列表优先？"
- 产出：三变体同一路由——a 指标卡阵列打头、b 列表优先 + 侧栏指标摘要、c 时间线为主；`?variant=` 切换 + 底部悬浮栏
- 合格判定：三个变体骨架完全不同；若三个只是卡片排列顺序不同，判不合格，重做
- 结论去处：任务描述写"采用 b，用户先关心今天要干什么，指标是派生信息"，分支 `prototype/dashboard-ia` 供回看

## 反例：不该触发原型的情况

- 答案纸上说得清（如"接口字段叫 name 还是 title"）→ 直接确认或直接改，不立项原型
- 用户要的是正式功能开发 → 走正常开发流程，原型不是替代品
- 用户口头说"做个页面"但无具体争议点 → 先用 AskUserQuestion 拆出要验证的设计问题，再进入本流程

## 反例：不合格的产出

- 三个变体只换了主题色和圆角 → 不算三版，重做
- 原型里写了单元测试和抽象层 → 违反丢弃式，删掉
- 原型改动直接落在正式代码文件上 → 全部迁出，正式文件保持零改动
- 原型提交进了 main → 移到 prototype/ 分支，main 恢复原状
