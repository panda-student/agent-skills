# 设计产物归档整合规范

## 一、适用范围

描述迭代工作区 UI 设计产物归档到项目知识图谱时的整合格式与合并规则。统一采用 MPA 结构，产物类型如下：

1. **首页 HTML**（`2.UI/index.html`，MPA 首页/默认入口，含业务内容 + 导航壳挂载点，无 D-编号）
2. **页面 HTML**（`2.UI/pages/D-XXX_{页面功能名称}.html`，独立页面，含内联 `<style>` 页面CSS + `<body>` 页面HTML + `<script>window.__pageId='路由ID';</script>` + 配套JS引用）
3. **页面配套 JS**（`2.UI/js/pages/D-XXX_{页面功能名称}.js`，函数定义 + IIFE 初始化，与 HTML 同名）
4. **公共 CSS**（`2.UI/css/common.css`，共享样式）
5. **公共 JS**（`2.UI/js/common.js`，含菜单配置 + 图标 Sprite + `pageRoute` 路由表 + `switchPage`（MPA location.href 跳转 + sessionStorage 持久化）+ `applyResponsiveZoom`）
6. **设计文档**（`2.UI/` 下的 `.md` 文件）
7. **图片素材**（`2.UI/` 下的 `.png/.jpg/.svg/.gif` 文件）

> **版本管理策略（全局）**：知识图谱归档时**直接覆盖**，不做版本递增。历史版本由 git 仓库管理，知识图谱始终保存最新全量状态。本规则适用于所有产物类型（JS/HTML/CSS/文档/图片），下文不再逐个重复声明。

---

## 二、源产物格式规范

### 2.1 源产物格式规范

统一采用 MPA 结构，迭代区产物结构如下（**扁平，不分模块目录**）：

```
2.UI/
├── index.html                    # 首页/默认入口（MPA，含业务内容 + 导航壳挂载点）
├── css/
│   └── common.css                # 公共样式
├── js/
│   ├── common.js                 # 公共JS（菜单配置+图标Sprite+路由+switchPage+zoom）
│   └── pages/                    # 各页面配套 JS
│       └── D-001_用户列表.js     # 配套JS（与HTML同名）
├── pages/                        # 各独立页面 HTML
│   └── D-001_用户列表.html       # 独立页面（含内联<style>+<body>+配套JS引用）
└── tmp/                          # 未通过自检的暂存区（不进 git，不归档）
```

| 产物 | 命名规则 | 说明 |
|------|---------|------|
| 首页 HTML | `index.html` | MPA 首页/默认入口，引用 `css/common.css` + `js/common.js`，无 D-编号 |
| 页面 HTML | `D-XXX_{页面功能名称}.html` | 独立页面，含内联 `<style>` 页面CSS + `<body>` 页面HTML + `<script>window.__pageId='路由ID';</script>` + 配套JS引用 |
| 页面配套 JS | `D-XXX_{页面功能名称}.js` | 与 HTML 同名，函数定义 + IIFE 初始化，存于 `js/pages/` |
| 公共 CSS | `common.css` | 共享样式，固定文件名 |
| 公共 JS | `common.js` | 含菜单配置 + 图标 Sprite + `pageRoute` 路由表 + `switchPage` + `applyResponsiveZoom`，固定文件名 |

> **关键规则**：修改页面内容/样式 → 改 `pages/D-XXX_{页面功能名称}.html`（CSS/HTML）+ `js/pages/D-XXX_{页面功能名称}.js`（交互）；修改导航菜单 → 只改 `js/common.js` 配置数据。`index.html` 为固定结构。

> **迭代区目录策略**：迭代区 `pages/` 采用**扁平结构**，不按模块分子目录。模块归属在归档时从文件元信息头读取，归入知识图谱的模块子目录。

#### 文件内元信息头（推荐）

每个 HTML 文件应在文件 `<head>` 顶部注释中包含以下元信息：

```html
<!--
  ============================================================
  JMBOS UI/UE 设计产物
  ============================================================
  产物编号: D-001
  页面名称: 用户列表
  页面类型: 列表页
  所属模块: 用户管理
  路由ID: user-list
  需求来源: PRD-20260101-001 / UC-USER-001
  所属迭代: 20260101-迭代需求名称
  最后更新: 2026-01-15
  ============================================================
-->
```

> ⚠️ 若文件内无元信息头，归档时从文件名和文件属性推断，并在报告中标注"元信息不完整"。

### 2.2 设计文档文件

#### 文件命名规范

```
{类型}-{模块/主题}.md
```

| 类型前缀 | 说明 |
|---------|------|
| `设计方案-` | 完整的设计方案说明 |
| `设计说明-` | 某个具体模块的设计说明 |
| `交互说明-` | 交互逻辑说明 |

**示例**：
```
设计方案-登录模块.md
设计说明-数据表格.md
组件决策-查询栏.md
```

### 2.3 图片素材文件

#### 文件命名规范

```
{用途}-{描述}.{扩展名}
```

| 用途前缀 | 说明 |
|---------|------|
| `screenshot-` | 页面截图 |
| `icon-` | 图标资源 |
| `illustration-` | 插图/示意图 |
| `export-` | 从 Figma 导出的资源 |

**示例**：
```
screenshot-用户列表页.png
icon-search.svg
export-按钮组件.png
```

## 三、元信息提取规则

### 3.1 提取优先级

当多个来源存在冲突时，按以下优先级取值：

| 优先级 | 来源 | 可信度 |
|--------|------|--------|
| 1（最高） | 文件内的元信息注释头 | 高 - 明确声明 |
| 2 | 文件名中的结构化信息 | 中 - 可能过时 |
| 3（最低） | 文件系统属性（修改时间等） | 低 - 不准确 |

### 3.2 页面标识提取规则

从文件中提取页面标识：

| 输入 | 提取结果 |
|------|---------|
| `D-XXX_{页面功能名称}.html` | 产物编号（从文件名提取 `D-XXX`）+ 路由ID（从 `.html` 内 `<script>window.__pageId='路由ID';</script>` 读取） |
| `index.html` | 首页/默认入口，不编路由ID，标记为 `INDEX` |

> ⚠️ 无路由ID的页面需提示用户确认是否需要补声明 `__pageId`。
> ⚠️ `index.html` 为首页/默认入口，不参与路由ID体系，按 §4.2 首页合并规则处理。

### 3.3 模块识别规则

归档时，每个 HTML 文件的模块归属按以下优先级确定：

| 优先级 | 识别方式 | 适用场景 | 规则 |
|--------|---------|---------|------|
| 1 | 元信息字段 | 有完整元信息头的文件 | 读取 `.html` 元信息注释头"所属模块" |
| 2 | common.js 路由表 | 路由表含模块映射 | 从 `pageRoute` 的模块字段读取 |
| 3 | 文件名推断 | 无元信息的文件 | 从文件名 `D-XXX_页面功能名称` 推断（如"用户列表"→"用户管理"） |
| 4 | 默认兜底 | 无法确定 | 归入"通用"目录，报告中标注 |

## 四、目标目录结构与合并规则

### 4.1 目标目录结构

知识图谱区采用**按模块分目录**结构：

```
02.项目知识图谱/
└── 2.UI/
    ├── 设计稿/                           # 设计产物
    │   ├── index.html                      # 首页/默认入口（MPA，根目录）
    │   ├── css/                            # 公共样式
    │   │   └── common.css
    │   ├── js/                             # 公共JS + 页面配套JS
    │   │   ├── common.js
    │   │   └── pages/                      # 页面配套 JS（按模块分目录，与 pages/ 同构）
    │   │       ├── 用户管理/
    │   │       │   ├── D-001_用户列表.js
    │   │       │   └── D-002_权限设置.js
    │   │       ├── 角色管理/
    │   │       │   └── D-003_角色管理.js
    │   │       └── 订单管理/
    │   │           ├── D-004_订单列表.js
    │   │           └── D-005_订单详情.js
    │   ├── pages/                          # 页面 HTML（按模块分目录）
    │   │   ├── 用户管理/
    │   │   │   ├── D-001_用户列表.html
    │   │   │   └── D-002_权限设置.html
    │   │   ├── 角色管理/
    │   │   │   └── D-003_角色管理.html
    │   │   └── 订单管理/
    │   │       ├── D-004_订单列表.html
    │   │       └── D-005_订单详情.html
    │   └── 素材资源/                       # 图片、图标等（如需）
    │       ├── 用户管理/
    │       │   ├── screenshot-用户列表.png
    │       │   └── icon-user.svg
    │       └── 通用/
    │           └── export-按钮组件.png
    │
    └── 设计文档/                         # 设计说明类文档
        ├── 用户管理-设计说明.md
        └── 通用组件-设计说明.md
```

> **存放规则**：
> - `index.html` 及公共资源（`css/`、`js/`）统一存放在 `设计稿/` 根目录，保持相对路径不变
> - 页面 HTML 按模块存放在 `pages/{模块名}/` 下
> - 页面配套 JS 按模块存放在 `js/pages/{模块名}/` 下，与 `pages/` 同构
> - `js/common.js` 中的 `pageRoute` 路径需带模块子目录（如 `pages/用户管理/D-001_用户列表.html`）

> **两区目录策略差异**：
> | 区域 | pages/ 结构 | 原因 |
> |------|------------|------|
> | 迭代区 | 扁平，不分目录 | 临时工作区，页面少，简单高效 |
> | 知识图谱区 | 按模块分目录 | 长期沉淀，页面多，便于检索管理 |

### 4.2 合并规则

> **核心策略**：直接覆盖（见 §一版本管理策略）。以下为各产物类型的处理矩阵。

#### 页面 HTML 与配套 JS

| 场景 | 条件 | 处理方式 | 目标路径 |
|------|------|---------|---------|
| **全新页面** | 知识图谱中无同名 | 复制 `.html` 到 `设计稿/pages/{模块}/` + `.js` 到 `设计稿/js/pages/{模块}/` | `pages/{模块}/D-XXX_{页面功能名称}.html` + `js/pages/{模块}/D-XXX_{页面功能名称}.js` |
| **已有页面更新** | 同名已存在 | **直接覆盖**原 `.html` 和 `.js` | `pages/{模块}/D-XXX_{页面功能名称}.html` + `js/pages/{模块}/D-XXX_{页面功能名称}.js` |
| **页面功能名称冲突** | 同名已存在 + 不同模块 | **暂停并请用户确认** | 待定 |

模块归属确定：见 §3.3 模块识别规则。

#### 首页（index.html）

| 场景 | 条件 | 处理方式 | 文件命名 |
|------|------|---------|---------|
| **首次归档** | 知识图谱 `设计稿/` 根目录下无 `index.html` | 复制到 `设计稿/` 根目录 | `index.html` |
| **再次归档** | 已存在 `index.html` | **直接覆盖**原文件 | `index.html` |

> `index.html` 是 MPA 首页/默认入口，不走路由ID匹配流程，不参与页面功能名称冲突判断。不归属任何单一模块，存放在 `设计稿/` 根目录。菜单数据基于设计系统 §3.8 菜单归属矩阵生成，禁止跨一级模块混入。

#### 公共资源

| 产物 | 合并规则 | 目标路径 |
|------|---------|---------|
| **公共 CSS**（`css/common.css`） | **直接覆盖** | `设计稿/css/common.css` |
| **公共 JS**（`js/common.js`） | **直接覆盖** | `设计稿/js/common.js` |

> `js/common.js` 的 `pageRoute` 路由表需带模块子目录路径，路径指向 `pages/{模块}/D-XXX_{页面功能名称}.html`（见 §4.3 路径转换）。

#### 设计文档

| 场景 | 处理方式 |
|------|---------|
| 新模块文档 | 新建 `{模块名}-设计说明.md` |
| 同模块已有文档 | **直接覆盖** |

> 设计文档不追加，避免历史堆积。文档演进由 git 管理。

#### 图片素材

| 操作 | 规则 |
|------|------|
| 复制 | 按模块归类到 `素材资源/{模块}/` 目录 |
| 冲突处理 | **直接覆盖** |
| 格式校验 | 跳过损坏文件（0字节或无法读取），记录到报告 |

### 4.3 资源引用路径自动修正

> **核心问题**：迭代区 `pages/` 扁平，知识图谱区 `pages/` 按模块分目录，两者的 `common.js` 路由表路径格式不同，归档和拉取时需自动转换。

#### 两区路由表路径格式

| 区域 | pageRoute 路径格式 | 示例 |
|------|-------------------|------|
| **迭代区** | `pages/D-XXX_{页面功能名称}.html`（扁平） | `pages/D-001_用户列表.html` |
| **知识图谱区** | `pages/{模块}/D-XXX_{页面功能名称}.html`（带模块） | `pages/用户管理/D-001_用户列表.html` |

#### 归档时路径转换（迭代区 → 知识图谱区）

```
转换前（迭代区 common.js）：
  user-list → pages/D-001_用户列表.html

转换后（知识图谱区 common.js）：
  user-list → pages/用户管理/D-001_用户列表.html
```

**转换逻辑**：
1. 遍历 `pageRoute` 中每条路由
2. 读取对应 `.html` 文件的元信息头"所属模块"字段（见 §3.3）
3. 在路径中插入模块目录：`pages/D-XXX_{页面功能名称}.html` → `pages/{模块}/D-XXX_{页面功能名称}.html`
4. 同步处理配套 JS 引用：`js/pages/D-XXX_{页面功能名称}.js` → `js/pages/{模块}/D-XXX_{页面功能名称}.js`
5. 无法确定模块的路由保持原路径，报告中标注

#### 拉取时路径转换（知识图谱区 → 迭代区）

```
转换前（知识图谱区 common.js）：
  user-list → pages/用户管理/D-001_用户列表.html
  role-mgmt → pages/角色管理/D-003_角色管理.html
  ... 全量20条

转换后（迭代区 common.js）：
  user-list → pages/D-001_用户列表.html
  role-mgmt → pages/D-003_角色管理.html
  ... 全量20条（路径扁平化，但路由表保持全量）
```

**转换逻辑**：移除路径中的模块目录层级即可（HTML 与配套 JS 引用路径同步移除）。

#### 其他资源路径

| 文件所在位置 | 引用路径 | 是否需修正 | 说明 |
|-------------|---------|-----------|------|
| `设计稿/index.html` | `css/common.css` | 否 | 同在根目录 |
| `设计稿/index.html` | `js/common.js` | 否 | 同在根目录 |
| `设计稿/js/common.js` | `pages/{模块}/D-XXX_{页面功能名称}.html` | 归档/拉取时转换 | 见上述转换逻辑 |
| `设计稿/pages/{模块}/D-XXX_{页面功能名称}.html` | 配套 JS 相对引用 | 归档/拉取时同步转换 | 引用相对路径 |
| `设计稿/pages/{模块}/D-XXX_{页面功能名称}.html` | 内联 CSS/HTML | 否 | 无外部引用 |

#### 执行逻辑

1. 归档复制完成后，验证 `index.html` 中引用的 `css/common.css`、`js/common.js` 路径有效
2. 验证 `js/common.js` 中 `pageRoute` 配置的 `pages/{模块}/D-XXX_{页面功能名称}.html` 路径有效
3. 验证 `js/pages/{模块}/D-XXX_{页面功能名称}.js` 配套 JS 路径有效（与 HTML 同名同模块目录）
4. 以下情况**跳过不处理**：
   - 绝对路径（以 `/` 或 `http` 开头）
   - CDN地址
   - Base64内联（`data:image/`）
5. 验证无残留即可，不做额外记录。

## 五、迭代区索引更新规范

### 5.1 迭代区索引格式

文件位置：`{迭代目录}/2.UI/索引.md`

索引为纯目录指引，每个条目一行：`- {文件名} — {一句话用途说明}`，不记录版本/日期/归档状态等修改细节。仅记录 `2.UI/` 下产出物，tmp不纳入索引。格式详见 [index-template.md](index-template.md) §三。

### 5.2 UI子目录索引格式

文件位置：`02.项目知识图谱/2.UI/索引.md`

## 六、特殊情况处理

### 6.1 跨模块页面

若一个页面涉及多个模块：
- **主模块**：取功能最核心的模块作为归属
- **交叉引用**：在其他模块的索引中添加引用链接

### 6.2 弹窗/抽屉类产物

弹窗和抽屉作为附属组件：
- 与其所属的主页面放在同一模块目录
- 弹窗 HTML 片段嵌入父页面 `.html` 的 `<body>` 中（不再独立成文件）
- 弹窗交互逻辑归入父页面配套 JS（`js/pages/{模块}/D-XXX_{主页面}.js`）

### 6.3 增量归档（同一迭代多次归档）

同一迭代可能分多次归档：
- 每次归档仅处理新增/变更的产物
- 已归档且无变更的产物跳过
- 报告中标注"本次归档"vs"历史累计"

### 6.4 回滚场景

> 版本管理由 git 仓库负责（见 §一）。

若需要撤回某次归档：
- 通过 `git revert` 或 `git checkout` 恢复到归档前的知识图谱状态
- 更新迭代区索引，将"已归档"改回正常状态
- **必须由用户明确要求才执行**

### 6.5 新增页面处理

新迭代中新增的页面（知识图谱中不存在的路由ID）：
- 归档时按模块归属复制 `.html` 到 `pages/{模块}/` + `.js` 到 `js/pages/{模块}/`
- `common.js` 路由表中新增对应条目（带模块路径，指向 `pages/{模块}/D-XXX_{页面功能名称}.html`）
- 菜单树中新增对应菜单项

### 6.6 删除页面处理

新迭代中删除的页面：
- 归档时从知识图谱 `pages/{模块}/` 删除对应 `.html`，从 `js/pages/{模块}/` 删除对应 `.js`
- `common.js` 路由表中删除对应条目
- 菜单树中删除对应菜单项
- **必须由用户明确要求才执行删除**

## 七、反向拉取规范（知识图谱 → 新迭代目录）

> **场景**：新迭代需要基于历史归档版本进行修改时，从知识图谱拉取相关产物到新迭代目录。

### 7.1 拉取策略

| 资源类型 | 拉取策略 | 原因 |
|---------|---------|------|
| `index.html` | **全量复制** | 固定结构，不随迭代变化 |
| `css/common.css` | **全量复制** | 公共样式，迭代区需自包含可预览 |
| `js/common.js` | **全量复制** | 保留完整路由表，归档覆盖后知识图谱不丢路由 |
| `pages/{模块}/D-XXX_{页面功能名称}.html` + `js/pages/{模块}/D-XXX_{页面功能名称}.js` | **按需拉取** | 只拉本次迭代涉及的页面 HTML + 配套 JS |

> **关键**：`js/common.js` 必须全量复制，因为归档时直接覆盖知识图谱的 `common.js`。如果迭代区只配了局部路由表，归档覆盖后知识图谱会丢失未迭代页面的路由。

### 7.2 拉取流程

1. 确定本次迭代涉及的页面路由ID清单（如 user-list、role-mgmt）
2. 按 §7.1 策略全量复制公共资源（index.html / common.css / common.js）
3. 按需复制页面 HTML + 配套 JS：
   - 从 `pages/{模块}/D-XXX_{页面功能名称}.html` 复制到迭代区 `pages/D-XXX_{页面功能名称}.html`（去掉模块目录层级）
   - 从 `js/pages/{模块}/D-XXX_{页面功能名称}.js` 复制到迭代区 `js/pages/D-XXX_{页面功能名称}.js`
4. 路径转换：`common.js` 的 `pageRoute` 从模块格式转为扁平格式（见 §4.3）
5. 验证：迭代区 `index.html` 双击可打开，本次拉取的页面可正常预览

### 7.3 拉取后的迭代区状态

```
01.项目迭代工作区/{新迭代}/2.UI/
├── index.html                          ← 全量复制（固定结构）
├── css/
│   └── common.css                      ← 全量复制（不改）
├── js/
│   ├── common.js                       ← 全量复制 + 路径扁平化（路由表全量，但pages/只有局部）
│   └── pages/                          ← 扁平结构，只含本次迭代涉及的页面配套 JS
│       ├── D-001_用户列表.js
│       └── D-005_权限设置.js
└── pages/                              ← 扁平结构，只含本次迭代涉及的页面 HTML
    ├── D-001_用户列表.html
    └── D-005_权限设置.html
```

> **迭代期间预览说明**：`common.js` 路由表是全量的（20条），但 `pages/` 目录只有本次拉取的文件（2个）。点击未拉取的页面时，`switchPage` 通过 `pageRoute` 路由未命中 / fetch HEAD 检测到目标 `.html` 不存在，显示"该页面非本次迭代范围"提示，不会出现404白屏。归档后知识图谱的 `index.html` 仍可看到全量页面。

### 7.4 拉取后的设计修改

拉取完成后，触发 `jmbos-uiue-design-system` 技能，以 `--update` 增量模式进入：
- 读取迭代目录内的历史 HTML + 配套 JS（已拉取的文件）
- 基于新需求增量修改
- 如新增页面 → `common.js` 路由表加条目 + `pages/` 加 `.html` + `js/pages/` 加 `.js`
- 如删除页面 → `common.js` 路由表删条目 + 删 `.html` + 删 `.js`
- 完成后归档（见 §四）
