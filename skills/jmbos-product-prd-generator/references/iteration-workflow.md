## 提取目标迭代版本

从用户输入中提取迭代版本号：

| 提取方式 | 示例输入 | 提取结果 |
|---------|---------|---------|
| 明确版本号 | "生成 v2.6 的需求文档" | 目标迭代：v2.6 |
| 明确版本号 | "修改 v2.5 的注册流程" | 目标迭代：v2.5 |
| 功能点 ID 反查 | "优化 F-SYS-001" | 从知识图谱 `功能点映射.md` 反查 F-SYS-001 所属的最新迭代和切片路径，并读取切片完整内容作为优化基础 |
| 无版本号 | "优化注册流程" | 询问用户：是当前最新迭代还是历史迭代？ |
| 无版本号 | "生成注册功能的需求" | 询问用户：属于哪个迭代版本？ |

**如果用户输入中没有明确迭代版本号，必须主动询问**，不得自行假设。

## 检查 PRD 文档是否存在

按以下优先级检查目标迭代是否已有 PRD 文档：

| 优先级 | 检查位置 | 说明 |
|-------|---------|------|
| 1 | 用户指定的文件路径 | 用户直接提供了 PRD 文件路径 |
| 2 | `02.项目知识图谱/1.产品/迭代文档/{原始文档名}.md` | 已归档到知识图谱的迭代文档 |
| 3 | `01.项目迭代工作区/{YYYYMMDD}-{迭代名称}/1.产品/` | 当前迭代工作区中未归档的 PRD 文档（文件命名 `{系统名称}-{模块描述}-需求说明书-{迭代版本}.md`，详见 prd-generation.md） |

**判定规则**：

| 检查结果 | 判定 | 后续路径 |
|---------|------|---------|
| 不存在对应迭代的 PRD | **新迭代 → 建新文档** | 进入「新迭代建文档」路径 |
| 已存在对应迭代的 PRD | **当前迭代 → 文档调优** | 进入「当前文档调优」路径 |

## 两条路径对比

| 维度 | 新迭代建文档 | 当前文档调优 |
|------|------------|------------|
| 触发条件 | 目标迭代无 PRD 文档 | 目标迭代已有 PRD 文档 |
| 基础骨架 | 从模板全新生成 | 加载已有 PRD 作为基础 |
| 知识图谱 | 按需读取（详见下方「新迭代建文档的知识图谱读取策略」）：纯新增功能读摘要+索引；涉及原有功能优化时读摘要+索引+相关切片 | 读摘要 + 相关切片，查约束避冲突 |
| 输出方式 | 写入新文件 | 原地修改已有文件 |
| 版本号策略 | 使用新迭代版本号 | 保持当前迭代版本号不变，更新修改记录 |
| 功能点 ID | 可新增功能点 ID（基于历史最大序号递增） | 优先复用已有功能点 ID，仅新增时递增。复用判定规则：操作入口不变 + 操作流程不变 + 功能类型不变 → 复用；新增入口 / 新增流程 / 类型变化 → 新建（详见 prd-generation.md 步骤五-C） |

### 新迭代建文档的知识图谱读取策略

新迭代建文档时，根据是否涉及原有功能优化，采取不同的知识图谱读取策略：

**场景识别**：

| 场景 | 识别信号 | 知识图谱读取策略 |
|------|---------|----------------|
| **纯新增功能** | 用户描述的是全新功能，未提及已有功能点 ID 或已有功能名称 | 读摘要（了解模块边界和已有规则避免冲突）+ 读索引（分配功能点 ID） |
| **涉及原有功能优化** | 用户提及已有功能点 ID（如"优化 F-TEA-001"）、已有功能名称（如"优化老师信息新增"）、或描述的优化内容涉及已有模块的功能 | 读摘要 + 读索引 + **读相关切片完整内容**（了解原有功能的前置条件、主要流程、业务规则、页面字段说明等，作为优化的基础） |

**涉及原有功能优化时的切片读取流程**：

1. 从用户输入识别优化的目标功能点（通过功能点 ID 或功能名称）
2. 查 `cached_feature_map`（或 `功能点映射.md`）→ 定位该功能点的切片文件路径
3. 读取切片完整内容 → 提取原有功能的前置条件、主要流程、异常流程、业务规则、页面交互说明、页面字段说明、EARS 需求列表
4. 基于原有功能内容 + 用户优化需求，生成新迭代的需求规格（标注变更点，保留未变更部分）
5. 功能点 ID 复用判定：操作入口不变 + 操作流程不变 + 功能类型不变 → 复用已有 ID；否则新建 ID

**关键原则**：涉及原有功能优化时，**禁止仅凭摘要和索引生成需求**——摘要只有一句话概述和关键规则，索引只有功能编号和版本，均不足以支撑对原有功能的精确优化。必须读取切片完整内容，确保优化基于原有功能的真实状态。

## 会话级知识缓存

同一会话中对同一迭代多次操作时，复用已读取的知识图谱数据，避免重复文件读取。

**缓存字段**：

| 字段 | 内容 | 有效期 |
|---------|------|--------|
| `cached_iteration` | 已缓存的迭代版本号 | 当前会话 |
| `cached_global_index` | 全局索引（迭代→模块映射、模块→功能点映射） | 当前会话 |
| `cached_feature_map` | 反向索引（功能点ID→模块+迭代+文件路径） | 当前会话 |
| `cached_modules` | 已读取的模块摘要（`摘要.md` 核心内容） | 当前会话 |
| `cached_max_ids` | 各模块功能点最大序号 | 当前会话 |
| `cached_slices` | 已读取的功能点切片（按需缓存） | 当前会话 |

**缓存决策**：

| 场景 | 缓存行为 |
|------|---------|
| 同一迭代、同一模块再次操作 | 复用缓存，不重新读取文件 |
| 同一迭代、不同模块操作 | 复用已缓存的全局索引，仅读取新模块摘要 |
| 不同迭代操作 | 清空缓存，重新读取 |
| 归档操作完成后（同会话内 archiver 更新了知识图谱） | 清空缓存，重新读取 |
| 用户明确要求"重新读取" | 清空缓存，重新读取 |
| 会话结束 | 缓存自动失效 |

## 知识图谱预读策略

> **两种"索引.md"的区分**：本技能涉及两种同名但不同的索引文件——
> - **工作区索引**（PRD 同目录 `索引.md`）：由 generator 在输出 PRD 时生成，用于快速定位该目录下的需求文档，详见 confirmation-workflow.md
> - **知识图谱全局索引**（`02.项目知识图谱/1.产品/索引.md`）：由 archiver 维护，记录迭代→模块映射和模块→功能点映射，本节预读的就是此文件

会话缓存未命中时，一次性预读全局索引和摘要数据到缓存，后续按需读取切片。

**预读范围**：

| 文件 | 读取内容 | 用途 | 缓存字段 |
|------|---------|------|---------|
| `索引.md`（全局） | 迭代→模块映射、模块→功能点映射（含模块中英文名） | 判断涉及模块、获取模块列表与中英文名映射 | `cached_global_index` |
| `功能点映射.md`（全局） | 功能点ID→模块+迭代+文件路径 | 功能点 ID 反查、序号递增 | `cached_feature_map` |
| 各模块 `摘要.md` | 模块职责、关键规则、约束条件 | 按需读取涉及模块的摘要 | `cached_modules` |
| 各模块 `切片/` | **不预读**，仅按需读取 | 功能点详情（仅在具体修改时读取） | `cached_slices` |

**预读流程**：

1. 阶段一判定需要读取知识图谱且缓存未命中 → 执行预读
2. 预读全局 `索引.md` → 获取迭代→模块映射和模块列表 → 写入 `cached_global_index`
3. 预读全局 `功能点映射.md` → 获取所有功能点ID到模块/迭代/路径的映射 → 写入 `cached_feature_map`，提取 `max_id` 写入 `cached_max_ids`
4. 按需读取涉及模块的 `摘要.md` → 写入 `cached_modules`
5. 预读完成，后续直接查缓存；仅当需要功能点详情时通过 `功能点映射.md` 定位切片路径并按需读取

**切片按需读取的触发场景**：
- 新迭代涉及原有功能优化 → 读取目标功能点的切片完整内容（详见上方「新迭代建文档的知识图谱读取策略」）
- 当前文档调优 → 读取相关切片查约束避冲突（详见下方「当前文档调优路径」）
- 用户明确询问某功能点的详情 → 读取该功能点切片

**快速定位场景**：

| 场景 | 查找方式 |
|------|---------|
| F-WRK-001在哪个文件？ | 查 `cached_feature_map` → 直接得到切片路径 |
| 当前 PRD 涉及哪些模块？ | 查 `cached_global_index` 迭代→模块映射，按"原始文档"列匹配 PRD 文件名 |
| teacher 模块有哪些功能？ | 查 `cached_global_index` 模块→功能点映射 |

> **查询规则**：迭代→模块映射以"原始文档"列为唯一标识。禁止用版本号查询——同一版本号（如 v1.0）可能对应多份不同模块的 PRD 文档，必须按当前 PRD 文件名匹配"原始文档"列。

**预读限制**：
- 仅预读全局 `索引.md` 和 `功能点映射.md`（通常 < 5KB），不预读切片
- 模块 `摘要.md` 按需读取（仅涉及模块时）
- 预读仅在缓存未命中时执行一次
- 知识图谱文件不存在（全新产品）时跳过预读

## 历史迭代调优警告

当用户指定了**非最新迭代**（历史版本）的修改需求时，必须给出警告：

```
⚠️ 警告：您指定的是历史迭代 v2.4，当前最新迭代为 v2.6。

历史迭代的需求文档通常不应再修改。请确认您的意图：
1. 实际要修改的是当前迭代 v2.6 的文档？
2. 确实需要修改历史迭代 v2.4 的归档文档？
3. 需要创建一个新迭代（如 v2.7）来包含这些优化？

请选择：
```

## 当前文档调优路径

当阶段一判定目标迭代已有 PRD 文档时，走「当前文档调优」路径。

### 步骤 1：解析用户优化意图

从用户输入中提取优化目标：

| 提取要素 | 说明 | 示例 |
|---------|------|------|
| 目标模块 | 优化涉及的功能模块 | "优化注册流程" → 模块=sys |
| 目标功能点 | 优化涉及的具体功能点 | "优化 F-SYS-001 的验证码逻辑" → F-SYS-001 |
| 优化类型 | 新增/修改/删除/调整优先级 | "添加邮箱注册" → 新增 |
| 优化内容 | 具体的优化描述 | "支持邮箱+验证码注册方式" |

### 步骤 2：读取产品知识图谱上下文

按以下优先级读取知识图谱中的上下文文件：

| 优先级 | 文件 | 路径 | 用途 |
|-------|------|------|------|
| 1 | 模块摘要 | `02.项目知识图谱/1.产品/模块/{模块中文名}/摘要.md` | 模块功能全景、关键业务规则、已知限制 |
| 2 | 模块索引 | `02.项目知识图谱/1.产品/模块/{模块中文名}/索引.md` | 迭代历史、功能点来源迭代和变更轨迹 |
| 3 | 相关切片 | `02.项目知识图谱/1.产品/模块/{模块中文名}/切片/` | 功能点的前置/后置条件、业务规则、页面交互 |
| 4 | 迭代文档 | `02.项目知识图谱/1.产品/迭代文档/` | 历史迭代的完整上下文和变更动机 |

**读取策略**：
- `摘要.md` 存在且 `last_updated` 在 30 天内 → 优先读摘要，按需读切片
- 摘要不存在或过期 → 读 `索引.md` 获取功能清单，再读相关切片
- 整个知识图谱不存在 → 退化为仅读当前 PRD 文档，提示用户"缺少产品知识图谱，优化建议可能不完整"

**从摘要中提取的关键信息**：

```
模块概述：{一句话理解模块职责}
核心功能：{已有功能清单，标注来源迭代}
关键业务规则：{所有约束条件，逐条列出}
已知限制：{当前版本的限制和异常处理}
```

### 步骤 3：读取当前 PRD 文档相关章节

1. 解析当前 PRD 的 YAML 头部，获取 `iteration`、`modules` 信息
2. 读取第 3.3 节功能模块与功能点划分表，定位目标模块的所有功能点
3. 读取第 4.x 节中目标模块的详细需求规格
4. 读取第 7 章验收标准中与目标模块相关的验收条件

### 步骤 4：分析变更影响与一致性约束

**一致性约束检查清单**：

| 检查维度 | 检查内容 | 检查方法 |
|---------|---------|---------|
| **业务规则冲突** | 新需求是否与已有业务规则矛盾 | 对照 `摘要.md` 中"关键业务规则"逐条比对 |
| **前后置条件破坏** | 修改是否影响其他功能点的前置/后置条件 | 检查相关切片正文中标注的跨模块引用（`→ 触发/引用 [模块英文名] F-{模块大写}-{序号}`） |
| **数据实体变更** | 是否新增/修改了核心业务实体字段 | 对照第 4 章功能点页面字段说明 |
| **验收标准牵连** | 修改是否导致已有验收标准失效 | 对照第 7 章验收标准逐条评估 |
| **优先级错位** | 优化需求的优先级是否与已有功能冲突 | 对照第 3.2 节用户故事地图的优先级 |

**跨模块影响分析**：如果目标模块的切片中标注了跨模块引用（如"触发[模块B-功能B]"），判断本次优化是否影响该引用，如影响则标注"需同步更新模块B"。

### 步骤 5：输出上下文摘要 + 优化方案

向用户输出上下文摘要，确认理解正确后再生成优化内容：

```
📋 上下文理解确认：

目标模块：sys（注册登录）
当前迭代：v2.4
已有功能：F-SYS-001 手机号注册、F-SYS-002 手机号登录、F-SYS-003 忘记密码

关键业务规则（已有）：
- 密码规则：长度8-20位，须包含大写、小写、数字
- 同一手机号每日获取验证码上限5次

您的优化需求：{用户原文}

变更影响分析：
- 影响功能点：F-SYS-001（手机号注册）
- 跨模块影响：无

是否基于以上理解继续生成优化方案？
```

### 优化需求生成规则

**增量修改原则**：

| 原则 | 说明 | 违反示例 | 正确示例 |
|------|------|---------|---------|
| **最小变更** | 只修改与优化需求直接相关的内容 | 重写整个模块的需求 | 仅修改目标功能点的相关字段 |
| **保留历史** | 不删除已有的功能点、业务规则 | 优化注册流程时删除了登录功能 | 保留登录功能不变，仅修改注册相关 |
| **标记变更** | 在修改记录中明确标注本次变更的内容和原因 | 修改记录只写"更新" | 修改记录写明"优化注册验证码逻辑：增加邮箱验证码通道" |

**冲突处理策略**：

| 冲突类型 | 处理方式 |
|---------|---------|
| 新规则与旧规则矛盾 | 优先采用新规则，在变更记录中标注旧规则已被替换及原因 |
| 优先级调整导致已有 P0 降级 | 警告用户，要求明确确认 |
| 移除已有功能点 | 警告用户该功能点已被其他模块引用，要求确认 |
