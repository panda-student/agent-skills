# Skill 测试验证清单

> ⚠️ **规则引用**：本清单仅列出检查项，所有规则定义以 [reference.md](./reference.md) 为权威源。

## 文件结构验证

### 目录结构
- [ ] 目录名称符合 [命名规则](./reference.md#命名规则)（小写、连字符、动名词）
- [ ] 目录位置正确（`.claude/skills/[skill-name]/`）
- [ ] SKILL.md 文件存在且为必需文件

### 可选文件
- [ ] reference.md（如需要）已创建
- [ ] examples.md（如需要）已创建
- [ ] templates/ 目录（如需要）已创建
- [ ] theories/ 目录（如需要）已创建

### 文件命名
- [ ] 所有文件名使用小写字母
- [ ] 文件名使用连字符分隔
- [ ] 文件扩展名正确（.md）

## Frontmatter 验证

### 必需字段
- [ ] `name` 字段存在
- [ ] `name` 与目录名一致
- [ ] `description` 字段存在
- [ ] `description` 遵循 [Description 编写公式](./reference.md#description-编写公式)

### 类型特定验证

**类型配置规则见** [reference.md - Skill 类型对比](./reference.md#skill-类型对比)

- [ ] **双模式型**：`user-invocable: true`，无 `disable-model-invocation`
- [ ] **参考型**：无 `user-invocable`，无 `disable-model-invocation`，只读权限
- [ ] **任务型**：`user-invocable: true`；敏感操作时 `disable-model-invocation: true`
- [ ] `allowed-tools` 遵循 [权限控制配置](./reference.md#权限控制配置)

## 触发测试

### 双模式型 Skill 触发测试
- [ ] 讨论相关话题时能自动触发（AI 自动调用）
- [ ] 斜杠命令可以正常调用（用户手动调用）
- [ ] 命令名称正确（`/[skill-name]`）

### 参考型 Skill 触发测试
- [ ] 讨论相关话题时能自动触发
- [ ] 不会在不相关话题中误触发
- [ ] 斜杠命令**不能**调用（无 user-invocable）

### 任务型 Skill 触发测试
- [ ] 斜杠命令可以正常调用
- [ ] AI识别到相关意图时也能自动触发（未设 `disable-model-invocation` 时）
- [ ] 执行流程符合预期

## 功能验证

- [ ] 核心功能正常工作：技能加载后能执行其主要声明功能
- [ ] 所有声明的功能都已实现：SKILL.md 核心功能表中每项均有对应实现
- [ ] 功能边界清晰，遵循 [单一职责原则](./theories/principles.md)：无跨领域功能混杂

---

## 脚本能力扩展验证（技能内含解析脚本/命令行工具时）

- [ ] 新增解析能力三件套同步：parsers 解析 + renderers 渲染 + 夹具样本与用例进快照（缺夹具样本 = 快照保护为空，未来改动可静默弄坏新能力而不报错）
- [ ] 能力清单/覆盖矩阵每项标签分类有实证样例支撑，无实证的标注「待验证」（分类错误会产生能力盲区：工具永不解析 → 梳理永远漏且无告警，2026-10-22 constraint 被误归「无逻辑不解析」实证）
- [ ] 预判新夹具样本对全局扫描类用例（refs/locate 等按字段/名称全库检索）的涟漪影响：新对象会让全局命中数变化，属预期变更，baseline 刷新对应模块即可

## 单一事实来源（SSOT）验证

**SSOT 规则与反模式案例见** [theories/principles.md](./theories/principles.md) 的 Single Source of Truth 原则

- [ ] 每条规则/约定在整个技能中只有一个定义处（reference.md 或文件内约定节）
- [ ] 同一文件内约定值无多处硬编码：路径、端口、URL 等约定值定义一次，其余位置用变量引用
- [ ] SKILL.md 流程段无细则抄写：每阶段仅「动作 + 锚点跳转」，细则唯一正主在 reference.md
- [ ] SKILL.md「硬约束/红线」仅保留无法从细则推导的强制项，不与细则逐条重复
- [ ] 索引/路由/踩坑表只写「场景 + 跳转」，不在跳转前复述规则摘要
- [ ] 会变化的值（端口/路径/数量）写弹性规则，不写死单值
- [ ] **改约定测试**：任选一条约定模拟修改，确认只需改动一处
- [ ] examples/演示内容未重复规则定义（规则细节链接到 reference.md）

## 依赖方向验证

**依赖抽象与反向依赖规则见** [theories/principles.md](./theories/principles.md#依赖抽象原则)

- [ ] 被依赖的底层技能（通用核心 / 基础能力）不引用依赖它的上层技能，无循环依赖
- [ ] 底层技能的路由表 / 边界 / 正文只用"由对应领域 SOP 负责"的能力化描述，不点名上层技能（含"→ `X` 技能""见 `X` 技能"）
- [ ] 上层技能引用底层技能属允许的单向依赖；一旦出现底层引用上层即判定违规
- [ ] 引用关系可画出明确方向（上层 → 底层），无双向边
