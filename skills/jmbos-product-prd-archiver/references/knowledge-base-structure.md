# 产品知识图谱结构说明

本文档描述归档器所操作的产品知识图谱目录结构和各文件的格式约定。知识图谱根目录为 `project_workspace/02.项目知识图谱/1.产品/`。

**核心原则**：每个功能点在 `切片/` 目录下始终只保留一份最新完整版本的切片文件。当新迭代修改了已有功能点时，将新内容合并整合到已有切片中，确保切片始终反映功能的当前完整状态。历史版本的完整内容可通过 `迭代文档/` 目录中的原始迭代文档追溯。

## 顶层结构

```

├── 索引.md                  # 全局索引（迭代→模块映射 + 模块→功能点映射）
├── 功能点映射.md            # 反向索引（功能点ID→模块+切片路径）
├── 迭代文档/                # 原始迭代文档存档（完整历史基线）
│   ├── OpenClaw-系统配置-需求说明书-v2.4.md
│   ├── OpenClaw-智能体工作台-需求说明书-v1.0.md
```

## 目录约定

| 目录 | 用途 | 写入策略 |
|------|------|---------|
| `迭代文档/` | 存放每次归档的原始迭代文档（完整历史基线） | 按迭代版本命名，同名覆盖 |
| `模块/{模块中文名}/` | 按模块组织需求知识，目录使用中文命名 | 自动创建，模块中文名来源于 PRD 3.3 节映射表 |
| `模块/{模块中文名}/切片/` | 存放该模块的功能点切片，每个功能点仅一份最新版本 | 新功能点直接写入；已有功能点合并整合后覆盖 |

## 文件格式

### 索引.md（全局） — 全局索引

全局索引位于知识图谱根目录，包含两个映射表：

#### 迭代→模块映射

> 每份 PRD 文档对应一个迭代，以"原始文档"列作为唯一标识。

| 迭代版本 | 涉及模块 | 归档日期 | 原始文档 |
|---------|---------|---------|---------|
| v2.4 | 系统配置, 内容管理 | 2025-06-01 | 迭代文档/OpenClaw-系统配置-需求说明书-v2.4.md |
| v1.0 | 智能体工作台 | 2026-06-03 | 迭代文档/OpenClaw-智能体工作台-需求说明书-v1.0.md |

**规则**：
- 以"原始文档"列（PRD 文件名）作为唯一标识，每份 PRD 文档对应一行
- 同一 PRD 文档重复归档时替换该行，新增 PRD 文档则新增行
- 按"归档日期"倒序排列（最新归档在前）
- "迭代版本"列仅作展示，不作为唯一键（同一版本号可能对应多份不同模块的 PRD 文档）
- "涉及模块"列使用模块中文名，逗号分隔

#### 模块→功能点映射

| 模块中文名 | 模块英文名 | 功能点数量 | 最新迭代 | 索引文件 |
|-----------|-----------|-----------|---------|---------|
| 智能体工作台 | workbench | 3 | v1.0 | 模块/智能体工作台/索引.md |
| 系统配置 | sys | 5 | v2.4 | 模块/系统配置/索引.md |

**规则**：
- 以"模块英文名"作为唯一标识（一个项目内模块英文名唯一）
- 功能点数量：统计该模块 `切片/` 下所有切片文件数量
- 最新迭代：取该模块所有切片当前版本的最大值（与摘要 `version` 字段取值规则一致）
- 模块英文名从功能点 ID 提取（`F-{MODULE}-{N}` → 转小写），与 YAML `modules` 字段交叉验证
- 通过"模块英文名"列持久化英文名到中文名的映射关系

### 功能点映射.md（全局） — 反向索引

反向索引位于知识图谱根目录，提供功能点 ID 到文件路径的直接映射。

| 功能点ID | 功能点名称 | 模块中文名 | 模块英文名 | 当前版本 | 变更迭代 | 切片文件路径 |
|---------|-----------|-----------|-----------|---------|---------|-------------|
| F-SYS-001 | 手机号注册 | 系统配置 | sys | v1.2 | v1.0, v1.1, v1.2 | 模块/系统配置/切片/F-SYS-001-手机号注册-v1.2.md |
| F-WRK-001 | 资源用量看板 | 智能体工作台 | workbench | v1.0 | v1.0 | 模块/智能体工作台/切片/F-WRK-001-资源用量看板-v1.0.md |

**规则**：
- 同一功能点 ID 已存在则更新（当前版本、变更迭代、切片文件路径、模块中文名），否则新增行
- 按功能点 ID 字母序排列
- 模块英文名从功能点 ID 提取（`F-{MODULE}-{N}` → `{MODULE}` → 转小写）
- 切片文件路径为相对于知识图谱根目录的路径

### 模块/索引.md — 模块需求索引卡

```markdown
# {模块中文名} 需求索引

> 模块英文名：{模块英文名}

| 功能编号 | 简述 | 当前版本 | 变更迭代 | 切片文件 |
|---------|------|---------|---------|---------|
| F-SYS-001 | 手机号注册 | v1.2 | v1.0, v1.1, v1.2 | 切片/F-SYS-001-手机号注册-v1.2.md |
| F-SYS-002 | 手机号登录 | v1.0 | v1.0 | 切片/F-SYS-002-手机号登录-v1.0.md |
| F-SYS-003 | 忘记密码 | v2.4 | v2.4 | 切片/F-SYS-003-忘记密码-v2.4.md |
```

**规则**：
- 标题使用模块中文名，副标题声明模块英文名
- 每个功能点仅一行
- 当前版本：该功能点最后一次修改的迭代版本
- 变更迭代：该功能点经历过的所有迭代版本，逗号分隔，按时间正序
- 同一功能编号已存在时更新"当前版本"、"变更迭代"和"切片文件"字段（合并整合后版本号变更导致文件名变化）
- 按功能编号字母序排列

### 摘要.md — 模块需求全景摘要

```markdown
---
module: sys
moduleName: 系统配置
last_updated: 2025-06-01
version: v2.4
status: 稳定
---

# 模块概述
本模块负责用户账户的全生命周期管理，包括注册、登录、密码管理和权限控制。

# 核心功能
1. 手机号注册 (v1.0)：支持手机号+短信验证码注册新账户
2. 手机号登录 (v1.0)：支持已有账户通过手机号+密码登录
3. 忘记密码 (v2.4)：通过手机号验证后重置密码

# 关键业务规则
- 密码规则：长度8-20位，必须包含大写字母、小写字母和数字
- 同一手机号每日获取验证码上限5次
- 登录成功后Token有效期30天
- 连续5次密码错误锁定15分钟

# 已知限制
- 单设备单点登录（新设备登录会挤掉旧设备）
- 当前仅支持手机号注册，不支持邮箱注册

# 变更记录
- v2.4：新增忘记密码功能
- v1.2：移除密码特殊字符规则
- v1.1：新增密码特殊字符规则
- v1.0：初始版本，手机号注册与登录
```

**规则**：
- 覆盖每次写入，体现完整状态
- 从所有当前切片中综合信息（每个功能点仅一份最新版本）
- 核心功能标注来源迭代
- 关键业务规则仅保留当前生效的规则
- 变更记录按迭代倒序排列
- version 字段取该模块所有切片中 `iterations` 列表中的最大版本号

### 切片/{功能编号}-{功能名称}-{最新迭代版本}.md — 功能点切片

```markdown
---
module: sys
moduleName: 系统配置
feature: 手机号注册
iteration: v1.2
date: 2025-06-01
id: F-SYS-001
iterations: [v1.0, v1.1, v1.2]
---

# F-SYS-001：手机号注册

- **功能 ID**：F-SYS-001
- **关联用户故事**：US-001
- **功能描述**：允许未注册访客通过手机号码接收短信验证码...
- **前置条件**：用户未登录、网络连接正常
- **后置条件**：系统创建新用户记录，状态为"已注册"
- **主要流程**：...
- **异常与分支流程**：...
- **业务规则**：...
- **页面交互说明**：...
- **页面字段说明**：...
- **EARS 格式需求列表**：...
```

**规则**：
- YAML 头部包含 `module`、`feature`、`iteration`、`date`、`id`、`iterations` 元数据
- `iteration`：该功能点最后一次修改的迭代版本
- `iterations`：该功能点经历过的所有迭代版本列表，按时间正序排列
- 正文自包含，脱离原始文档仍能理解
- 正文始终为合并整合后的最新完整内容
- 文件名包含最新迭代版本号，反映切片当前合并到的版本，每次合并整合后需更新文件名中的版本号

**合并整合策略**：

当同一功能编号的切片已存在时：
1. 读取已有切片的完整内容
2. 读取本次迭代中该功能点的完整内容
3. **判断新内容的完整性**（按以下信号识别）：
   - **完整描述**（满足以下任一信号）→ **替换**：用新内容覆盖旧切片正文
     - 信号 A：功能点标题不含"（v{X.Y} 增强）"标注
     - 信号 B：功能点正文包含完整要素（Standard/Full 深度为 12 项要素，Lite 深度为 5 项核心要素：功能ID、关联用户故事、功能描述、主要流程、EARS格式需求列表）
     - 信号 C：功能点正文未引用其他迭代版本（无"本功能点在 vX.Y 基础上增强""见 vX.Y 迭代文档"等引用块）
   - **增量变更**（满足以下任一信号）→ **合并**：将变更应用到已有切片中，保留未变更的部分，移除被删除的部分
     - 信号 A：功能点标题包含"（v{X.Y} 增强）"标注
     - 信号 B：功能点正文以引用块开头，声明"本功能点在 vX.Y 基础上增强，仅描述 vX.Y 变更内容"
     - 信号 C：功能点正文仅包含部分要素（如仅页面字段说明+业务规则+EARS列表，缺少前置条件、主要流程等）
4. 更新 YAML 头部的 `iteration`、`date`、`iterations` 字段
5. 更新切片文件名中的版本号为本次迭代版本（如 `F-SYS-001-手机号注册-v1.1.md` → `F-SYS-001-手机号注册-v1.2.md`），删除旧文件名的文件
6. 合并后的切片必须自包含、完整

**废弃功能点处理**：

当 YAML 头部 `deprecated_features` 字段声明了废弃功能点时：
1. 删除对应的切片文件（如存在）
2. 在模块索引卡（`模块/{模块中文名}/索引.md`）中移除该功能点的行
3. 在 `功能点映射.md` 中移除该功能点的行
4. 在归档报告中列出所有已处理的废弃功能点

## 命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| 模块目录名 | 模块中文名，来源于 PRD 3.3 节映射表 | `系统配置`、`内容管理`、`智能体工作台` |
| 切片文件名 | `{功能编号}-{功能中文名称}-{最新迭代版本}.md` | `F-SYS-001-手机号注册-v1.2.md` |
| 迭代文档名 | 直接使用源文档原始文件名 | `OpenClaw-系统配置-需求说明书-v2.4.md` |
| 索引文件名 | 固定为 `索引.md` | `索引.md` |
| 摘要文件名 | 固定为 `摘要.md` | `摘要.md` |
