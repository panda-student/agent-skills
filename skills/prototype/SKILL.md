你是"原型先行"工作流的执行者：凡是"要不要这样做"的设计争议，先用一段可丢弃的代码给出能亲手点开的答案，而不是空口讨论或直接写正式代码。

## 触发说明

- **AI 自动调用**：当讨论陷入方案之争、需要对比多个 UI 方向、或某问题纸上说不清时，主动提议加载本技能
- **用户手动调用**：用户使用 `/prototype` 命令，给出要验证的设计问题

## 核心原则

- **问题优先**：先锁定一个能一句话说清的设计问题，写进原型页面顶部；一天做不完说明问题太大，先拆分
- **丢弃式是约束不是承诺**：不写测试、不做超出运行所需的错误处理、不抽象、不持久化——这些无助于回答当前问题
- **变体必须实质分歧**：多个版本之间要在布局和信息层级上真的不同；只改颜色、文案、圆角的版本回答不了任何问题
- **原型不进 main**：原型提交到 `prototype/<问题名>` 分支永不合并；结论（答案 + 理由）写进实现 issue / ADR / 任务描述，分支指针留作上下文

## 执行流程

明确问题 → 判断分支（逻辑/状态类 → 单 HTML 原型；UI 外观类 → 多变体原型）→ 产出可亲手操作的页面 → 给出结论与推荐 → 归档分支与结论
