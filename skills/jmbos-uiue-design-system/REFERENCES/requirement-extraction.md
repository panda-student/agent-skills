# 需求完整性提取指引

> 版本: v1.0 | 最后更新: 2026-08-07
>
> **定位**：本文件是需求文档（文字/PRD）输入的**完整性保障文档**。SKILL.md §3 定义入口和强制规则，本文件提供五维度提取方法、清单格式、防遗漏机制和覆盖校验。
>
> **适用场景**：用户提供需求文档/文字描述/PRD 作为输入时（非 Figma 设计稿）。Figma 输入走 [figma-workflow.md](./figma-workflow.md)。

## 1. 核心问题：为什么会遗漏

需求识别遗漏的三大根因：

| 根因 | 表现 | 本文件对策 |
|------|------|-----------|
| **只提取了"看得见的"** | 只识别页面类型和主要组件，漏掉字段细节、异常状态、边界交互 | 五维度强制提取（§2） |
| **没有清单化产出** | 需求只在脑中分析，没有逐条列出，无法追溯和校验 | 《需求完整清单》强制产出（§3） |
| **没有反向校验** | 实现完成后不回比对需求，遗漏项未被发现 | 需求覆盖校验（§5） |

## 2. 五维度强制提取

> ⚠️ **强制规则**：以下五个维度**必须逐条提取**，任一维度为空时必须在《疑点清单》中说明原因，禁止默认"无"。

### 2.1 功能维度（F — Function）

**提取什么**：页面需要实现的业务功能点。

**提取方法**：
- 逐句扫描需求文档中的动词短语（"新增""查询""编辑""删除""导出""导入""审批""分配"等）
- 每个功能点记录：功能名 + 触发入口 + 操作对象 + 预期结果
- 检查是否有"批量""定时""条件触发"等隐性功能

**检查清单**：
- [ ] 所有 CRUD 操作都已列出？
- [ ] 所有按钮/链接对应的动作都已识别？
- [ ] 批量操作/定时任务/条件触发是否遗漏？
- [ ] 权限相关功能（查看/编辑/删除权限）是否识别？

**输出格式**：

| # | 功能名 | 触发入口 | 操作对象 | 预期结果 | 备注 |
|---|--------|---------|---------|---------|------|
| F1 | 新增用户 | 新增按钮 | 用户表单 | 弹窗填写→保存→刷新列表 | 必填校验 |
| F2 | 批量删除 | 勾选+删除 | 选中行 | 二次确认→删除→刷新 | 至少选1条 |

### 2.2 字段维度（D — Data/Field）

**提取什么**：表单字段、表格列、详情字段的完整清单。

**提取方法**：
- **表单字段**：逐个识别字段名 + 类型 + 是否必填 + 校验规则 + 默认值 + 选项来源
- **表格列**：逐列识别列名 + 数据类型 + 是否可排序 + 是否可筛选 + 宽度/对齐
- **详情字段**：逐个识别字段名 + 展示形式（文本/标签/图片/链接）+ 格式化规则

**检查清单**：
- [ ] 每个表单字段都标注了类型（输入框/下拉/日期/单选/多选/开关/上传）？
- [ ] 必填字段是否标注？
- [ ] 下拉/单选/多选的选项来源（静态枚举/接口/字典表）是否说明？
- [ ] 校验规则（长度/格式/范围/唯一性）是否提取？
- [ ] 字段间联动（如选A显示B）是否识别？
- [ ] 表格所有列都已列出，含操作列？

**输出格式**：

| # | 字段名 | 类型 | 必填 | 校验规则 | 默认值 | 选项来源 | 备注 |
|---|--------|------|------|---------|--------|---------|------|
| D1 | 用户名 | 文本输入 | 是 | 2-20字符 | - | - | 唯一 |
| D2 | 角色 | 下拉单选 | 是 | - | - | 接口/role/list | 联动D3 |
| D3 | 权限 | 多选 | 是 | - | - | 接口/perm/list | D2变化时刷新 |

### 2.3 交互维度（I — Interaction）

**提取什么**：用户与页面的所有交互行为，含标准交互和自定义交互。

**提取方法**：
- **标准交互**：对照 [page-interactions.md](./page-interactions.md) IX1-IX12 检查覆盖
- **自定义交互**：从需求文档中识别非标准交互，逐条记录

**检查清单**：
- [ ] 查询/重置交互已覆盖？
- [ ] 新增/编辑/删除交互已覆盖？
- [ ] 分页交互已覆盖？
- [ ] 表单保存交互已覆盖？
- [ ] 导航切换/侧边展开收起已覆盖？
- [ ] 表格行操作已覆盖？
- [ ] Tab切换已覆盖？
- [ ] **自定义交互**：需求中是否有跳转/弹窗/抽屉/拖拽/右键/快捷键等非标准交互？
- [ ] **跨页面交互**：是否有页面跳转传参？

**输出格式**：

| # | 交互名 | 类型 | 触发 | 动作 | 适用页面 | 备注 |
|---|--------|------|------|------|---------|------|
| I1 | 查询 | 标准(IX1) | 点击查询按钮 | 提交查询→刷新表格 | 列表页 | - |
| I2 | 点击用户名跳转详情 | 自定义 | 点击表格用户名链接 | switchPage('user-detail')+传id | 列表页→详情页 | 跨页面 |
| I3 | 角色联动权限 | 自定义 | 角色下拉change | 刷新权限多选项 | 表单页 | 字段联动 |

### 2.4 状态维度（S — State）

**提取什么**：数据和页面的各种状态。

**提取方法**：
- **数据状态**：每条数据的生命周期状态（如：待审批/审批中/已通过/已驳回）
- **页面状态**：空数据/加载中/加载失败/无权限/网络异常
- **按钮状态**：可用/禁用/加载中，及触发条件
- **表单状态**：新建模式/编辑模式/只读模式

**检查清单**：
- [ ] 数据状态枚举是否完整？
- [ ] 每个状态对应的视觉表现（标签颜色/图标）是否说明？
- [ ] 空数据/加载中/错误态是否设计？
- [ ] 按钮的禁用条件是否提取？

**输出格式**：

| # | 状态名 | 归属 | 枚举值 | 视觉表现 | 触发条件 | 备注 |
|---|--------|------|--------|---------|---------|------|
| S1 | 审批状态 | 数据 | 待审批/审批中/已通过/已驳回 | 灰/蓝/绿/红标签 | - | 影响按钮可用性 |
| S2 | 空数据 | 页面 | - | 空状态插图+提示文案 | 查询无结果 | - |

### 2.5 异常维度（E — Exception）

**提取什么**：异常边界和错误处理。

**提取方法**：
- 逐句扫描需求文档中的"如果""当...时""异常""失败""错误""超时"等条件语句
- 识别校验失败、接口异常、权限不足、数据冲突等异常场景

**检查清单**：
- [ ] 必填校验失败提示是否设计？
- [ ] 格式校验失败提示是否设计？
- [ ] 唯一性冲突提示是否设计？
- [ ] 接口超时/失败处理是否说明？
- [ ] 删除关联数据的提示是否设计？
- [ ] 权限不足的处理是否说明？

**输出格式**：

| # | 异常场景 | 触发条件 | 处理方式 | 提示文案 | 备注 |
|---|---------|---------|---------|---------|------|
| E1 | 用户名重复 | 保存时接口返回409 | 表单字段下方红色提示 | "该用户名已存在" | 不关闭弹窗 |
| E2 | 删除关联数据 | 删除时接口返回409 | Toast提示 | "存在关联数据，无法删除" | - |

```

需求来源：{需求文档路径/粘贴文本/口头描述}

## F — 功能清单（共N项）
| # | 功能名 | 触发入口 | 操作对象 | 预期结果 | 备注 |

## D — 字段清单（共N项）

| # | 字段名 | 类型 | 必填 | 校验规则 | 默认值 | 选项来源 | 备注 |

| # | 列名 | 数据类型 | 可排序 | 可筛选 | 宽度/对齐 | 备注 |
```

## 4. 防遗漏机制

### 4.1 数量下限检查

> 类似 §3.6 组件防遗漏（列表≥7/详情≥5/表单≥6/弹窗≥6），需求也有数量下限参考。

| 页面类型 | 功能(F)下限 | 字段(D)下限 | 交互(I)下限 | 状态(S)下限 | 异常(E)下限 |
|---------|-----------|-----------|-----------|-----------|-----------|
| 列表页 | ≥3(查询/新增/删除) | 表格列≥4 | ≥5(IX1-5) | ≥2(空数据/加载) | ≥2(校验/接口) |
| 详情页 | ≥1(返回) | 详情字段≥5 | ≥2(IX8/12) | ≥1(空数据) | ≥1(接口) |
| 表单页 | ≥1(保存) | 表单字段≥4 | ≥1(IX7) | ≥1(新建/编辑) | ≥3(必填/格式/接口) |
| 弹窗 | ≥1(确认/取消) | 弹窗字段≥2 | ≥1(打开/关闭) | ≥1(加载) | ≥2(校验/接口) |

> ⚠️ **低于下限必须解释原因**：在《疑点清单》中说明"为何该维度项数偏少"，禁止默认"无"。

### 4.2 关键词扫描

扫描需求文档，确保以下关键词对应的需求都已提取：

| 维度 | 触发关键词 |
|------|-----------|
| 功能(F) | 新增/创建/编辑/修改/删除/查询/搜索/筛选/导出/导入/下载/上传/审批/分配/复制/批量/定时/自动 |
| 字段(D) | 字段/输入/下拉/选择/日期/开关/上传/必填/校验/默认值/选项/枚举/联动 |
| 交互(I) | 点击/跳转/弹窗/抽屉/展开/收起/切换/拖拽/右键/快捷键/悬浮/联动 |
| 状态(S) | 状态/待/中/已/未/启用/禁用/空/加载/失败/异常/只读/可编辑 |
| 异常(E) | 如果/当...时/异常/失败/错误/超时/冲突/不存在/无权限/重复 |

### 4.3 疑点清单

> 提取过程中遇到以下情况必须列入《疑点清单》，向用户确认：
> - 需求描述模糊（如"用户管理"未说明具体功能）
> - 需求缺失（如只说了查询未说新增，但业务上通常需要）
> - 需求矛盾（如"必填"但未说明校验规则）
> - 需求超出规范（如需要拖拽排序，规范未覆盖）

## 5. 需求覆盖校验

> ⚠️ **强制规则**：自检阶段（§7）必须执行需求覆盖校验，反向验证每个需求项是否已实现。

### 5.1 需求→实现映射表

在实现完成后，产出《需求覆盖校验表》：

```
《需求覆盖校验表》— {页面名称}
校验时间：{YYYY-MM-DD HH:mm}

| 需求编号 | 需求内容 | 对应实现 | 覆盖状态 | 备注 |
|---------|---------|---------|---------|------|
| F1 | 新增用户 | 弹窗嵌入D-001_用户列表.html + js/pages/D-001_用户列表.js saveUser() | ✅已实现 | - |
| D2 | 角色下拉 | <select id="role"> | ✅已实现 | 选项来自接口 |
| I2 | 点击用户名跳转 | js/pages/D-001_用户列表.js rowClick handler → switchPage('user-detail') | ⚠️部分实现 | 缺少传参 |
| E1 | 用户名重复提示 | js/pages/D-001_用户列表.js validation | ❌未实现 | 待补充 |

汇总：已实现 N/N，部分实现 N/N，未实现 N/N
```

### 5.2 覆盖率标准

| 覆盖状态 | 说明 | 处理 |
|---------|------|------|
| ✅ 已实现 | 需求项有对应实现且功能完整 | 通过 |
| ⚠️ 部分实现 | 需求项有对应实现但功能不完整 | 列入待修复，说明缺什么 |
| ❌ 未实现 | 需求项无对应实现 | **禁止输出至 2.UI/**（必须补全或向用户说明） |

> ⚠️ **禁止跳过**：覆盖率 100% 是输出至 `2.UI/` 的前置条件。未实现的项必须补全或在《疑点清单》中说明原因并经用户确认可延期。
