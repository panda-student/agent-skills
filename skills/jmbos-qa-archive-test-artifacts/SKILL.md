将指定迭代工作区 `4.测试/` 下的测试产物，按功能模块进行整合，归档到 `02.产品知识图谱/4.测试/` 下对应的全局目录中。归档后迭代源文件保留不删除，仅在索引中标注"已归档"。

## 工作流

必须严格按照以下工作流顺序执行，禁止跳步或绕过。

### 1. 确定迭代目录

- 从用户输入中提取迭代名称（如 `20260101-迭代需求名称`）。
- 若用户未指定迭代，必须中断并列出 `ai_workspace/01.产品迭代工作区/` 下所有已有迭代目录供用户选择。
- 迭代目录完整路径格式：`ai_workspace/01.产品迭代工作区/{YYYYMMDD-迭代名称}/`。
- 确认后读取该迭代目录下的 `4.测试/索引.md` 了解已有产物。

### 2. 扫描源测试产物

扫描 `{迭代目录}/4.测试/` 下的测试用例（`测试用例/*.md`）和自动化覆盖清单（`自动化测试/API/api_{project}_{module}_coverage.md` 或 `自动化测试覆盖清单/API/api_{project}_{module}_coverage.md`）。

产物格式说明和模块提取规则详见 [archive-spec.md](references/archive-spec.md)。

### 3. 读取知识图谱已有产物

读取 `ai_workspace/02.项目知识图谱/4.测试/` 下的已有内容——测试用例模块文件（`测试用例/{模块名}-测试用例.md`）和自动化覆盖清单（`自动化覆盖清单/API自动化/api_{project}_{module}_coverage.md`），用于后续合并时的去重和更新判断。目录结构详见 [archive-spec.md](references/archive-spec.md)。

### 4. 整合测试用例（按功能模块）

整合逻辑严格按 [archive-spec.md](references/archive-spec.md) 执行，核心步骤：

1. **分组**：按模块字段分组，无法推断的归入"未分类"。
2. **合并**：同模块 → 整体替换旧用例，新模块 → 新建文件。
3. **过大提示**：单模块合并后超过 50 条用例，提示用户是否拆分子模块。

### 5. 整合自动化覆盖清单（按 Project + Module）

整合逻辑严格按 [archive-spec.md](references/archive-spec.md) 执行，核心步骤：

1. 读取迭代区和知识图谱中对应 project_module 的清单（不存在则新建）。
2. 按 `功能模块 + 关联接口` 匹配去重：已有 → 更新（保留原创建时间，操作类型改"修改"），无匹配 → 追加（"新增"）。
3. 更新基本信息中的"最后更新"时间和"累计覆盖接口数"。

清单格式参考 [coverage-template.md](references/coverage-template.md)。

### 6. 输出归档报告

完成后输出汇总报告，至少包含：

- **归档迭代**：迭代名称
- **测试用例整合**：按模块列出 → 合并前/合并后用例数、新增/更新/覆盖的 TC 编号
- **覆盖清单整合**：按 project_module 列出 → 新增/更新的接口记录数
- **注意事项**：若有模块未分类、冲突已自动处理等情况，显式说明

## 约束

- 归档后迭代源文件**不删除**，仅在索引中标注"已归档"。
- 若迭代区无测试产物（`4.测试/` 下为空或仅有索引文件），中断并提示用户。
- 禁止修改上游产物（PRD、接口文档等），禁止修改迭代区中的非测试文件。
