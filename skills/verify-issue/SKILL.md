# PMS 问题验证与同类排查

> 职责边界：本技能只读核实、不动代码，产出「结论 + 排查清单 + 方案素材」；拍板交互（决策包一次拍板、范围边界确认）交给 `grill-me` 技能，拍板前禁止动代码。

## 缺陷受理验证

- Grep 定位 Controller → 顺调用链读 VO/SQL/Service
- 核对接口出参是否含契约字段（对照 docs/api 与 docs/business 业务文档）
- 输出「问题属实/误报」结论 + 数据源分析表（字段 → 来源表列 → 现状）

## 同类问题排查（缺陷确认属实后必做，误报跳过）

- 排查维度（按缺陷特征选相关项，至少覆盖代码同源与数据同源）：
  - **同字段**：同名字段/同业务含义别名在其他模块的取数（Grep 字段名/别名/SQL 片段）
  - **同写法**：同类 VO 映射、注解缺失、SQL 出参别名、校验器照搬前端规则等范式复用处
  - **同数据来源**：同一张表/共有接口的多个消费方是否受同一根因影响
  - **同前端形态**：同类页面组件/低代码菜单列绑定 prop 同样偏差
- 输出「同类问题清单」：位置（文件:行/菜单项）、场景、是否同源、影响面、是否本次一并处理；无同类也明确写「已排查，无同类」
- 清单随受理结论一并交用户拍板本次处理范围（全量/仅本次实例），禁止只修单点收尾；用户选「仅本次实例」时收尾登记遗留

## 需求输入物作废识别（缺陷/功能通用）

- 规格书为 Excel 时逐格检查删除线：openpyxl 读 `cell.font.strike is True` 即该行需求作废；不能只看 `*` 必填标记与备注（字段作废后备注可能残留旧口径）
- 删除线作废的字段不得作为校验/必填依据；已实现的必填/联动/条件显隐应回退，DDL 新增同名字段与列一并下线
- 实例：2026-10-21 工程采购规格书「是否立项项目」两格删除线漏检，后端按残留备注实现条件必填致 UAT 提交被拦

## 功能开发现状核实

- 通读需求输入物，Grep 定位涉及模块/Controller/VO/SQL，摸清现状
- 输出需求梳理表：**业务目标**（一句话）、**数据层**（表/字段、DDL 需求与存量数据影响）、**接口层**（新增/修改接口与出入参契约）、**前端层**（页面/组件、是否需前端配合）、**范围边界**（做什么/不做什么）
- 需求有歧义逐项澄清后进方案设计

## 结论与方案素材输出要求

- **证据链闭环为标配**：每个关键改动点与字段映射结论附证据（i18n 文案比对、业务文档归类、实体字段唯一性、DB 实际数据）；用户质疑时逐项出示
- **多方案供选**：关键改动点至少 2 个候选（改动范围/影响面/成本风险对比），标注推荐项与理由，禁止单方案默认执行（fast path 例外：单方案给推荐）
- **数据来源映射**：跨模块字段名不一致给别名方案（SQL 出参加别名 `SELECT a.b AS c`，不改存量表结构与前端）
- **共用接口场景化扩展**：被多方共用的接口需为单一场景加差异行为时，入参 DTO 加可选场景参数（默认不传保持原行为）+ 实现处按参数分流，禁止复制新接口；样板 `ProjectClosureSelectQueryDTO.ignoreInvestmentAmountThreshold`
- **改名连锁成本**：用户问「为什么不统一命名」时，给改名连锁成本清单（DDL+迁移+前端引用+文档）vs 最小改动对比，推荐最小方案；统一治理列独立重构任务不混入本次
- 拍板未含的同类遗留项在收尾登记；素材齐备后交 `grill-me` 一次性列全拍板项
