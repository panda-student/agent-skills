## 最常见错误预防

### 坑一：数字加点加空格

这是最容易踩的坑，踩了就报错：`Unsupported markdown: list`

**问题在哪：**
```
[1. 步骤一]
[2. 步骤二]
```
Mermaid 把 `1.` 当成 Markdown 列表了，直接报错。

**怎么改：**
```
✅ [1.步骤一]       去掉空格，最简单
✅ [① 步骤一]       用带圈数字
✅ [(1) 步骤一]     加括号
✅ [步骤1：步骤一]  加前缀
✅ [Step 1 - 步骤一] 用英文前缀
```

**带圈数字速查：**
```
① ② ③ ④ ⑤ ⑥ ⑦ ⑧ ⑨ ⑩
⑪ ⑫ ⑬ ⑭ ⑮ ⑯ ⑰ ⑱ ⑲ ⑳
```

### 坑二：子图名字有空格没加引号

**问题在哪：**
```
subgraph 核心处理模块
    A --> B
end
```
名字带空格，解析器不认识。

**怎么改：**
```
✅ subgraph core["核心处理模块"]
    A --> B
end

或者干脆别用空格：
✅ subgraph core_module
    A --> B
end
```

### 坑三：引用节点用显示名

**问题在哪：**
```
Title --> 核心处理模块
```
你写的是显示名，解析器找不到。

**怎么改：**
```
✅ Title --> core
```
用定义时的 ID，别用显示名。

## 常见报错排查

### 报错：`Parse error: Unsupported markdown: list`

**原因：** 数字加点加空格

**解决：** 去掉空格，或用带圈数字，或加前缀

### 报错：`Expecting 'SEMI', 'NEWLINE', 'EOF'`

**原因：**
- 子图名字有空格没加引号
- 引用用了显示名而不是 ID
- 有特殊字符没处理

**解决：**
- 子图用 `id["名字"]` 格式
- 引用用 ID
- 引号换成 `『』`，括号换成 `「」`

### 报错：`unexpected character`

**原因：**
- 特殊字符没处理
- 引号格式不对
- 语法写错了

**解决：**
- 替换问题字符
- 检查节点定义语法
- 检查箭头语法

### 图画不出来或画歪了

**可能原因：**
- 方向没写
- 节点 ID 重名
- 引用的节点没定义
- 样式声明语法错误

**检查一下：**
- `graph TB/LR` 写了没
- 每个 ID 唯一吗
- 先定义再引用
- 样式语法正确吗

## 平台差异

| 平台 | 说明 |
|-----|------|
| Obsidian | Mermaid 版本较旧，语法更严格，`<br/>` 只在圆形节点有效 |
| GitHub | 支持较好，但跟 Obsidian 可能略有差异 |
| Mermaid Live Editor | 最新版，测试语法用这个 |

**建议：** 在 Mermaid Live Editor 先测试，确认没问题再放到文档里。

## 快速参考

### 安全的数字写法
```
✅ [1.文字]  [① 文字]  [(1) 文字]  [Step 1: 文字]
❌ [1. 文字]
```

### 安全的子图写法
```
✅ subgraph id["名称"]    subgraph simple_name
❌ subgraph 名字带空格
```

### 安全的节点引用
```
✅ NodeID --> AnotherID
❌ "显示名" --> "另一个显示名"
```

### 安全的特殊字符
```
✅ 『』替代引号，「」替代括号
❌ " 未转义引号，() 在问题上下文中
```

## 最终检查清单

画完图，过这个清单：

- [ ] 没有 `数字. 空格` 模式
- [ ] 子图名字有空格的都加了 `id["名字"]` 格式
- [ ] 引用都用 ID，没用显示名
- [ ] 没用 Emoji（用颜色或文字代替）
- [ ] 箭头语法正确
- [ ] 节点 ID 不重复
- [ ] 先定义后引用
- [ ] 颜色语法正确
- [ ] 方向已指定

有问题对照着改，基本都能解决。
