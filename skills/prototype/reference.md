# prototype 技能详细规格

## 两分支判断

- 问题在问"这样运转对不对 / 状态怎么流转 / 边界怎么处理" → 逻辑分支
- 问题在问"这应该长什么样 / 怎么布局 / 信息怎么呈现" → UI 分支
- 两者都涉及 → 先逻辑后 UI：先在单 HTML 里敲定运转模型，再在模型之上对比外观
- 判断不出或问题太大 → 用 AskUserQuestion 与用户对齐，或先拆分问题

## 问题定义

- 一句话写清本次要回答的问题，原样放在原型页面顶部
- 每个原型只回答一个问题；"做个完整登录页"不是设计问题，是开发任务，先拆出具体争议点
- 问题超过一天工作量 → 太大，拆分后再动手

## 丢弃式边界

做：

- 硬编码贴近项目真实形态的数据（真实字段名、真实量级、真实脏数据）
- 临时代码、console.log、写死的开关
- 内联一切（CSS/JS/图标），目标是双击即开

不做：

- 测试、CI、lint 配套
- 超出演示所需的生产级错误处理
- 抽象、组件库引入、持久化、鉴权
- 修改任何正式代码文件（原型一律落在 prototype/ 目录或独立文件）

## 逻辑原型规格（单 HTML）

- 单个 `.html` 文件，零外部依赖，无需构建和服务器，双击即可打开
- 页面顶部一行写清本次回答的问题
- 底层逻辑是纯函数 reducer/状态机，与渲染完全分离，回答敲定后可整体搬进正式代码
- 页面必须提供三样东西：
  - **状态面板**：直接展示内部状态（当前值、模式、计数器等），让用户看见看不见的东西
  - **自由操作按钮**：可乱序触发任意动作，不强制按预设路径走
  - **分场景引导演示**：常见/边界路径一键回放（如"连续快速保存""离线后恢复"）
- 文件与分支命名：`prototype/<问题名>.html`，问题名用 kebab-case 英文

## UI 变体规格（默认三版）

- 所有变体跑在同一个 HTML / 同一路由上，通过 `?variant=a|b|c` 切换；页面悬浮底部栏提供切换按钮
- 默认做三版；问题特别简单可减为两版，但不得为凑数降低分歧度
- 合格变体的标准：布局骨架、信息层级、交互模型至少一个维度结构性不同；只改颜色、文案、圆角、图标不算变体，重做
- 尽量在真实页面、真实数据下渲染；项目支持独立路由/独立入口时挂上去跑
- 每个变体顶部标注一句话设计取向（如"指标驱动：先看总量再看明细"）
- 成功的标志是用户反馈类似"B 的头部 + C 的侧栏"——变体的价值就是让组合式决策成为可能

## 归档与结论

- 原型文件提交到 `prototype/<问题名>` 分支（`git checkout -b prototype/<问题名>`），永不合并进 main
- 会话结束时给出：结论（选哪个方案 / 状态怎么运转）、理由、下一步落点（实现 issue 或 ADR）
- 结论文字写进实现 issue / ADR / 任务描述；正文保留指向原型分支的指针，原型代码本身不删除
- 若在独立会话中运行原型工作：只把结论与分支名带回原会话，不把原型过程的上下文带回去
