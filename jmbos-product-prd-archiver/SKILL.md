# 迭代需求归档器

> **Freedom Level: High** — 本技能为文档处理型，提供分步流程和文件结构约定，不包含可执行脚本。

## When to Use

- 用户上传或提交了一份迭代需求文档（如 v2.4.md）
- 用户明确要求归档某个迭代需求
- 用户请求将 PRD 拆分为模块需求切片
- 用户需要更新模块需求全景摘要

将一份完整的迭代需求文档归档到 `project_workspace/02.项目知识图谱/1.产品/` 知识库中，自动拆解为按模块存储的独立切片，并更新全局索引、模块索引卡和最新摘要。同时保留迭代原始文档作为历史基线。

**核心原则**：每个功能点在 `切片/` 目录下始终只保留一份最新完整版本的切片文件。当新迭代修改了已有功能点时，将新内容合并整合到已有切片中，确保切片始终反映功能的当前完整状态。历史版本的完整内容可通过 `迭代文档/` 目录中的原始迭代文档追溯。

## 前置要求

- 迭代需求文档必须遵循标准 PRD 模板，包含 YAML 头部（含 `modules` 字段）和按编号切割的功能点。
- 假设知识库结构为：

```
project_workspace/02.项目知识图谱/1.产品/
  索引.md           # 全局索引（迭代→模块映射 + 模块→功能点映射）
  功能点映射.md     # 反向索引（功能点ID→模块+切片文件路径）
  迭代文档/          # 存放原始迭代文档（完整历史基线，可追溯任意版本）
  模块/             # 按模块存放切片、索引、摘要
    <模块中文名>/    # 使用中文命名，如"系统配置"、"评级申请管理"
      索引.md
      摘要.md
      切片/          # 每个功能点仅保留一份最新完整版本的切片
```

## 参数

| 参数 | 类型 | 必需 | 默认值 | 说明 |
|------|------|------|--------|------|
| `iteration_doc_path` | string | 是 | - | 迭代需求文档的完整路径 |
| `dry_run` | boolean | 否 | false | 如果为 true，只输出将要执行的操作而不实际写入文件 |

## 工作流程

### 步骤 1：读取并验证文档

> **dry_run 模式**：如果 `dry_run` 为 true，所有写入操作均不执行，仅输出计划报告。后续各步骤不再重复声明。

1. 读取 `{iteration_doc_path}` 指定的文件。
2. 解析文档头部的 YAML 元数据块，提取以下字段：

| 字段 | 必需 | 说明 |
|------|------|------|
| `iteration` | 是 | 迭代版本标识，如 `v2.4` |
| `modules` | 是 | 涉及的模块列表，如 `["sys", "cms", "workbench"]` |
| `date` | 是 | 迭代日期，格式 `YYYY-MM-DD` |
| `depth` | 是 | 深度策略，取值 `Lite` / `Standard` / `Full`，用于判断功能点要素完整性和合并策略 |
| `deprecated_features` | 否 | 废弃功能点 ID 列表，如 `["F-SYS-003"]`，用于步骤 2-B 执行删除处理 |
| `name` | 否 | 文档名称 |
| `description` | 否 | 文档描述 |

3. **输入验证**：
   - 如果 `modules` 字段缺失或为空，输出错误提示并中止：
     ```
     ❌ 归档失败：文档缺少 modules 字段。
     请在文档 YAML 头部添加 modules 字段，格式示例：
     modules: ["sys", "cms", "workbench"]
     ```
   - 如果 `iteration` 字段缺失，输出错误提示并中止。
   - 如果 `date` 字段缺失，使用当前日期作为默认值并给出警告。
   - 如果 `depth` 字段缺失，默认按 `Standard` 处理并给出警告。
   - 如果文件不存在或无法读取，输出错误并中止。
6. **文档结构验证**：
   - 检查第 3.3 节「功能模块与功能点划分」表格是否存在，不存在则输出错误并中止（归档器依赖此表提取模块映射）。
   - 检查第 4 章「功能需求详述」章节是否存在，不存在则输出错误并中止（归档器主要提取此章节的切片）。
   - 检查是否存在 `####` 级别且包含 `F-` 前缀的功能点标题，不存在则输出警告（文档无可提取的功能点）。

4. **提取模块中英文名称映射**：
   - 读取 PRD 文档第 3.3 节「功能模块与功能点划分」表格，提取「模块」（中文名）和「模块英文名称」列，构建中英文映射表。
   - 映射表示例：`{"sys": "系统配置", "cms": "内容管理", "workbench": "智能体工作台"}`
   - **目录命名规则**：模块目录使用**中文名称**，如 `模块/系统配置/`、`模块/评级申请管理/`。
   - 如果 3.3 节无法解析或缺失，回退使用 YAML `modules` 字段中的英文名作为目录名，并输出警告。
   - **模块重命名检测**：将本次提取的中英文映射表与知识图谱全局 `索引.md` 的「模块→功能点映射」表对比。如果发现同一模块英文名对应的中文名发生变化（如"系统配置"→"系统管理"），或 YAML `modules` 字段中的英文名与已有索引不一致，输出警告提示用户确认是否为模块重命名。确认后，将旧模块目录重命名为新中文名，并更新所有索引和映射中的模块名引用。
5. **提取废弃功能点列表**：
   - 读取 YAML 头部的 `deprecated_features` 字段（可选，字符串数组），获取本次迭代声明废弃的功能点 ID 列表。
   - 这些功能点表示在本次迭代中被移除，归档器需在步骤 2-B 中执行删除处理。
   - 如果 `deprecated_features` 字段不存在或为空，跳过删除处理。

### 步骤 2：提取功能点切片

**定位功能点**：在文档中查找功能点所在的章节。功能点通常位于 `## 4. 功能需求详述` 章节下，以 `####` 级别标题标记。识别标志为标题中包含 `F-` 前缀的功能点 ID（如 `F-SYS-001`、`F-TEA-001`）。

**提取规则**：
- 对于每个功能点，提取从功能点标题开始到下一个**同级或更高级标题**之前的所有内容。
- 功能点标题支持以下两种格式：
  - `#### F-{模块大写}-{序号} {功能名称}`（当前格式，如 `#### F-TEA-001 老师信息新增`）
  - `#### 4.X.Y 功能点 F-{模块大写}-{序号}：{功能名称}`（旧格式，如 `#### 4.1.1 功能点 F-SYS-001：手机号注册`）
- **识别方式**：以 `####` 级别标题中包含 `F-` 前缀的功能点 ID 为识别标志，不依赖固定标题格式

**切片内容生成**：

每个切片文件必须自包含，包含以下内容：

```markdown
---
module: {模块英文名}
moduleName: {模块中文名}
feature: {功能名称}
iteration: {最新迭代版本}
date: {最新迭代日期}
id: {功能编号，如 F-SYS-001}
iterations: [{该功能点经历过的所有迭代版本，按时间正序}]
---

# {功能编号}：{功能名称}

{功能点完整内容（合并整合后的最新版本）}
```

**YAML 头部字段说明**：
- `module`：模块英文名，用于程序化识别和与 YAML `modules` 字段交叉验证
- `moduleName`：模块中文名，用于目录命名和展示，来源于 3.3 节映射表
- `iteration`：该功能点最后一次修改的迭代版本
- `date`：最后一次修改的迭代日期
- `iterations`：该功能点经历过的所有迭代版本列表，按时间正序排列，如 `[v1.0, v1.1, v1.2]`。首次归档时仅包含当前迭代

**模块归属确定**：
- 直接从功能点 ID 中提取模块英文名。功能点 ID 格式为 `F-{模块英文名大写}-{序号}`（如 `F-SYS-001`），其中 `F-` 为固定前缀，模块前缀 `SYS` 对应的模块英文名为 `sys`（全小写）。
- 提取规则：取功能点 ID 中第二个连字符 `-` 之前、`F-` 之后的部分，转为全小写，即为模块英文名。即 `F-{MODULE}-{N}` → 提取 `{MODULE}` → 转小写 → 模块英文名。
- **目录名确定**：通过步骤 1 中构建的中英文映射表，将模块英文名映射为中文目录名。如 `sys` → `系统配置`，`application` → `评级申请管理`。
- 与 YAML 头部的 `modules` 列表交叉验证：如果提取的模块英文名不在 `modules` 列表中，则标记为警告并在报告中列出，但仍使用提取的模块英文名作为归属。
- 作为兜底：如果功能点 ID 无法提取模块前缀（如格式不符），回退到从章节标题中推断（如 `### 4.1 评级申请管理 (application)`）。如果中英文映射表中无对应项，回退使用模块英文名作为目录名。

**切片文件名规范**：
- 格式：`{功能编号}-{功能中文名称}-{最新迭代版本}.md`
- 功能编号格式 `F-{MODULE}-{N}`，如 `F-SYS-001`
- 功能中文名称直接使用切片标题中的中文功能名称
- 最新迭代版本：该切片最后一次合并整合的迭代版本号
- 示例：`F-SYS-001-手机号注册-v1.2.md`、`F-WRK-001-资源用量看板-v1.0.md`
- 如果功能中文名称提取困难，使用功能编号代替：`{功能编号}-{最新迭代版本}.md`
- **注意**：文件名中的版本号反映切片当前合并到的最新迭代版本，每次合并整合后需更新文件名中的版本号

**合并整合策略**：

当同一功能编号的切片已存在时，按以下策略合并整合：

1. 读取已有切片的完整内容
2. 读取本次迭代中该功能点的完整内容
3. **判断新内容的完整性**（按以下信号识别）：
   - **完整描述**（满足以下任一信号）→ **替换**：用新内容覆盖旧切片正文，旧切片中的信息不再保留
     - 信号 A：功能点标题不含"（v{X.Y} 增强）"标注
     - 信号 B：功能点正文包含完整要素（Standard/Full 深度为 12 项要素，Lite 深度为 5 项核心要素：功能ID、关联用户故事、功能描述、主要流程、EARS格式需求列表）
     - 信号 C：功能点正文未引用其他迭代版本（无"本功能点在 vX.Y 基础上增强""见 vX.Y 迭代文档"等引用块）
   - **增量变更**（满足以下任一信号）→ **合并**：将变更应用到已有切片中，保留未变更的部分，移除被删除的部分
     - 信号 A：功能点标题包含"（v{X.Y} 增强）"标注
     - 信号 B：功能点正文以引用块开头，声明"本功能点在 vX.Y 基础上增强，仅描述 vX.Y 变更内容"
     - 信号 C：功能点正文仅包含部分要素（如仅页面字段说明+业务规则+EARS列表，缺少前置条件、主要流程等）
   - **兜底机制**：当格式信号不明确（既不满足完整描述信号也不满足增量变更信号）时，比较新内容与已有切片的要素数量。如果新内容要素数量明显少于已有切片（如已有切片含 12 项要素，新内容仅含 5 项），提示人工确认是替换还是合并，避免因格式信号缺失导致误判为替换而丢失已有内容。
4. 更新 YAML 头部：
   - `iteration` → 更新为本次迭代版本
   - `date` → 更新为本次迭代日期
   - `iterations` → 追加本次迭代版本（如尚未包含）
5. 更新切片文件名中的版本号为本次迭代版本（如 `F-SYS-001-手机号注册-v1.1.md` → `F-SYS-001-手机号注册-v1.2.md`），删除旧文件名的文件
6. 合并后的切片必须自包含、完整，脱离任何迭代文档仍能独立理解该功能的当前状态

### 步骤 2-B：处理废弃功能点

在提取功能点切片后，处理 YAML 头部 `deprecated_features` 字段声明的废弃功能点：

1. 从步骤 1 提取的废弃功能点 ID 列表中，逐个处理：
   - 查 `功能点映射.md`（或 `cached_feature_map`）定位其切片文件路径
   - 删除对应的切片文件（如存在）
   - 在模块索引卡（`模块/{模块中文名}/索引.md`）中移除该功能点的行
   - 在 `功能点映射.md` 中移除该功能点的行
2. 如果废弃功能点在知识图谱中不存在（已被删除或从未归档），输出警告并跳过
3. 在归档报告中列出所有已处理的废弃功能点

**注意**：删除操作不可逆，建议在 `dry_run` 模式下先确认废弃清单。

### 步骤 3：按模块分发切片

1. 根据步骤 1 中构建的中英文映射表，将 YAML `modules` 字段中的英文名映射为中文目录名，在 `project_workspace/02.项目知识图谱/1.产品/模块/` 下创建对应的中文命名模块目录（如不存在）。
2. 为每个模块创建 `切片/` 子目录（如不存在）。
3. 对每个切片文件：
   - **新功能点**（`切片/` 下不存在同 ID 文件）：直接保存到 `模块/{模块中文名}/切片/` 下
   - **已有功能点**（`切片/` 下已存在同 ID 文件）：按步骤 2 的合并整合策略处理后保存为新文件名（版本号已更新），并删除旧文件名的文件

**写入失败处理**：
- 如果某个切片文件写入失败，记录错误日志，跳过该切片，继续处理后续切片。
- 最终报告中列出所有失败的切片及原因。

### 步骤 4：更新模块索引卡

对每个涉及的模块，读取或创建 `模块/{模块中文名}/索引.md`。

**索引卡格式**：

```markdown
# {模块中文名} 需求索引

> 模块英文名：{模块英文名}

| 功能编号 | 简述 | 当前版本 | 变更迭代 | 切片文件 |
|---------|------|---------|---------|---------|
| F-SYS-001 | 手机号注册 | v1.2 | v1.0, v1.1, v1.2 | 切片/F-SYS-001-手机号注册-v1.2.md |
| F-SYS-002 | 手机号登录 | v1.0 | v1.0 | 切片/F-SYS-002-手机号登录-v1.0.md |
```

**更新规则**：
1. 如果 `索引.md` 不存在，创建新文件，包含标题和表格头。
2. 每条记录对应一个功能点（一个功能点仅一行）。
3. **字段说明**：
   - 功能编号：功能点 ID
   - 简述：功能点名称
   - 当前版本：该功能点最后一次修改的迭代版本
   - 变更迭代：该功能点经历过的所有迭代版本，逗号分隔，按时间正序
   - 切片文件：切片文件相对路径
4. **更新规则**：如果同一功能编号已存在，更新其"当前版本"、"变更迭代"和"切片文件"字段（合并整合后版本号变更导致文件名变化）；否则新增一行。
5. **排序规则**：按功能编号字母序排列。

### 步骤 5：更新模块摘要

对每个涉及的模块，生成一份新的完整需求摘要，覆盖 `模块/{模块中文名}/摘要.md`。

**核心原则**：摘要必须体现该模块**从最初到当前迭代**的完整功能全景，禁止只写增量。

**生成流程**：
1. 读取已有的 `摘要.md`（如果存在）。
2. **增量策略**：仅当本次归档修改了该模块的切片（新增、合并或废弃）时才重新生成摘要。未修改模块跳过摘要更新，避免不必要的全量重写。
3. 读取 `切片/` 目录下所有切片文件（每个功能点仅一份最新版本）。
4. 综合所有切片内容，生成覆盖全生命周期的完整摘要。

**摘要模板**：

```markdown
---
module: {模块英文名}
moduleName: {模块中文名}
last_updated: {当前日期}
version: {最新迭代版本}
status: 稳定
---

# 模块概述
{一句话描述模块目的，基于所有切片内容综合得出}

# 核心功能
1. {功能1} ({来源迭代})：{一句话说明}
2. {功能2} ({来源迭代})：{一句话说明}
...

# 关键业务规则
- {规则1}
- {规则2}
...

# 已知限制
- {限制说明}
...

# 变更记录
- {迭代版本}：{本次迭代对该模块的变更摘要，如"新增手机号注册功能"、"移除密码特殊字符规则"}
...
```

**摘要生成指南**：
- **模块概述**：综合所有切片，用一句话概括模块负责的业务范围。
- **核心功能**：按功能编号排序，每条包含来源迭代和一句话说明。
- **关键业务规则**：从所有切片中提取独特的业务规则（去重），仅保留当前生效的规则。
- **已知限制**：从所有切片中汇总异常分支和限制条件。
- **变更记录**：按迭代倒序排列，每条记录该迭代对模块的变更摘要。从切片 YAML 头部的 `iterations` 字段和索引卡的变更迭代信息中提取。
- **version 字段取值规则**：取该模块所有切片中 `iterations` 列表中的最大版本号（即该模块最后一次修改的迭代版本），而非本次归档迭代版本。

### 步骤 6：保留迭代原始文档

将原始迭代文档复制到 `project_workspace/02.项目知识图谱/1.产品/迭代文档/` 目录下。

**文件命名规则**：
- **直接使用源文档的原始文件名**，保留完整语义描述，不做重命名
- 示例：归档 `OpenClaw-智能体会话-需求说明书-v2.0.md` 后，`迭代文档/` 下生成 `OpenClaw-智能体会话-需求说明书-v2.0.md`

**覆盖策略**：
- 如果 `迭代文档/` 下已存在同名文件，默认覆盖。
- 如果 `dry_run` 为 true，仅输出覆盖预警。

### 步骤 7：更新全局索引和反向索引

在 `project_workspace/02.项目知识图谱/1.产品/` 根目录下更新两个全局索引文件。

**7.1 更新全局索引 `索引.md`**

读取或创建 `索引.md`，包含两个映射表：

```markdown
# 产品需求全局索引

> 本文件由归档器自动维护，记录所有迭代与模块的映射关系。

## 迭代→模块映射

> 每份 PRD 文档对应一个迭代，以"原始文档"列作为唯一标识。

| 迭代版本 | 涉及模块 | 归档日期 | 原始文档 |
|---------|---------|---------|---------|
| v2.4 | 系统配置, 内容管理 | 2025-06-01 | 迭代文档/OpenClaw-系统配置-需求说明书-v2.4.md |
| v1.0 | 智能体工作台 | 2026-06-03 | 迭代文档/OpenClaw-智能体工作台-需求说明书-v1.0.md |

## 模块→功能点映射

| 模块中文名 | 模块英文名 | 功能点数量 | 最新迭代 | 索引文件 |
|-----------|-----------|-----------|---------|---------|
| 智能体工作台 | workbench | 3 | v1.0 | 模块/智能体工作台/索引.md |
| 系统配置 | sys | 5 | v2.4 | 模块/系统配置/索引.md |
```

**更新规则**：
- **迭代→模块映射**：以"原始文档"列（PRD 文件名）作为唯一标识，每份 PRD 文档对应一行。同一 PRD 文档重复归档时替换该行，新增 PRD 文档则新增行。按"归档日期"倒序排列（最新归档在前）。"迭代版本"列仅作展示用途，不作为唯一键（因为同一版本号如 v1.0 可能对应多份不同模块的 PRD 文档）。"涉及模块"列使用模块中文名，逗号分隔（来源于 3.3 节映射表）
- **模块→功能点映射**：以"模块英文名"作为唯一标识（一个项目内模块英文名唯一），统计该模块 `切片/` 下所有切片文件数量，更新功能点数量和最新迭代。模块中文名来源于 3.3 节映射表，模块英文名从该模块下功能点 ID 提取（`F-{MODULE}-{N}` → 转小写），与 YAML `modules` 字段交叉验证。"最新迭代"取该模块所有切片当前版本的最大值（与摘要 `version` 字段取值规则一致）
- **模块英文名持久化**：通过"模块英文名"列持久化存储英文名到中文名的映射关系，generator 可通过此列反向获得模块英文名

**7.2 更新反向索引 `功能点映射.md`**

读取或创建 `功能点映射.md`，提供功能点ID到文件路径的直接映射：

```markdown
# 功能点反向索引

> 通过功能点ID直接定位到模块和切片文件路径。由归档器自动维护。

| 功能点ID | 功能点名称 | 模块中文名 | 模块英文名 | 当前版本 | 变更迭代 | 切片文件路径 |
|---------|-----------|-----------|-----------|---------|---------|-------------|
| F-SYS-001 | 手机号注册 | 系统配置 | sys | v1.2 | v1.0, v1.1, v1.2 | 模块/系统配置/切片/F-SYS-001-手机号注册-v1.2.md |
| F-WRK-001 | 资源用量看板 | 智能体工作台 | workbench | v1.0 | v1.0 | 模块/智能体工作台/切片/F-WRK-001-资源用量看板-v1.0.md |
```

**更新规则**：
- 同一功能点ID已存在则更新（当前版本、变更迭代、切片文件路径、模块中文名），否则新增行
- 按功能点ID字母序排列
- 模块英文名从功能点ID提取（`F-{MODULE}-{N}` → `{MODULE}` → 转小写）

## 错误处理

| 错误场景 | 处理方式 |
|---------|---------|
| 文档文件不存在 | 输出错误并终止 |
| YAML 解析失败 | 输出错误详情并终止 |
| 缺少 modules 字段 | 输出错误并提示用户补充 |
| 缺少 iteration 字段 | 输出错误并终止 |
| 缺少 date 字段 | 使用当前日期，输出警告 |
| 缺少 depth 字段 | 默认按 Standard 处理，输出警告 |
| 功能点无法归属模块 | 标记为 unknown，继续处理，报告中列出 |
| 废弃功能点在知识图谱中不存在 | 输出警告，跳过该功能点 |
| 文档缺少 3.3 节或第 4 章 | 输出错误并终止 |
| 文档无功能点可提取 | 输出警告，继续处理（仅更新原始文档和全局索引） |
| 模块重命名检测到名称变更 | 输出警告，提示用户确认后执行重命名 |
| 合并策略信号不明确 | 提示人工确认是替换还是合并 |
| 模块目录创建失败 | 输出错误并终止 |
| 切片文件写入失败 | 记录错误，跳过该切片，继续处理 |
| 摘要文件写入失败 | 记录错误，报告中列出 |
| dry_run 模式 | 不写入任何文件，仅输出计划报告 |

## 注意事项

1. 始终保持原始迭代文档与模块切片之间的可追溯性（切片 YAML 头部包含 `iterations` 字段记录变更历史）。
2. 确保切片内容自包含，脱离原文仍能理解。
3. 摘要的更新必须体现模块的"当前完整状态"，禁止只写增量。
4. 索引卡每个功能点仅一行，通过"变更迭代"字段记录完整变更历史。
5. 切片目录下每个功能点仅保留一份最新完整版本，新迭代修改已有功能点时必须合并整合而非简单覆盖。
6. 历史版本的完整内容通过 `迭代文档/` 目录中的原始迭代文档追溯，无需在切片目录中保留历史版本。
7. 所有文件操作使用 UTF-8 编码。
8. YAML 头部 `deprecated_features` 字段声明的废弃功能点需在步骤 2-B 中执行删除处理，删除切片文件并清理索引。
9. 合并策略需根据 YAML `depth` 字段判断功能点要素完整性：Lite 深度功能点仅含 5 项核心要素，不应因要素数量不足而误判为增量变更。
