## 一、节点尺寸（强制对齐系统原版）

| 节点类型 | 标准尺寸 | 说明 |
|---------|---------|------|
| StartEvent | 30×30 | 固定 |
| EndEvent | 28×28 | 固定 |
| UserTask | 100×46 | 短名；**长名自动加宽** |
| Task/ServiceTask 等 | 100×80 | 固定 |
| XORGateway/ANDGateway/ORGateway | 40×40 | 固定 |

**UserTask 长名加宽规则**（对齐系统行为）：
- 中文按 14px/字，英文按 8px/字
- 文字宽度 + 20px padding，最小 100
- 原版 19 个 UserTask 是 100 宽，2 个长名是 186/215 宽

## 二、节点坐标布局（relayoutNodes 算法）

**不直接用 bpmn-auto-layout 的坐标**（它按 100×80 布局，改成真实尺寸后会重叠），而是：

1. **保留拓扑顺序**：bpmn-auto-layout 算出"谁在前谁在后"的顺序
2. **按行聚类**：中心 y 差异 < 40 视为同行
3. **每行紧凑重排**：按真实宽度从左到右排列，基础节点间距 `GAP_X=50`
4. **强制中心 y 对齐**：
   - 主行（含 StartEvent）→ 所有节点中心 y = StartEvent 中心 y
   - 其他行 → 中心 y = 主行 y + （原 layoutCy 偏移）

**效果**：节点不重叠、主行水平对齐（用户明确要求的规则）。

### 自适应画布与内容居中

在全部节点和边路由完成后执行 `fitContentToCanvas`，不得在边尚未生成时提前确定画布大小。

内容范围必须包含：

- 所有节点矩形。
- 所有边的完整 bounds，包括上方/下方绕行槽。
- StartEvent、EndEvent 和 Gateway 名称的标签安全区。

默认参数：

| 常量 | 默认值 | 用途 |
|---|---:|---|
| `CANVAS_PADDING_X` | 60 | 内容左右对称边距 |
| `CANVAS_PADDING_Y` | 60 | 内容上下对称边距 |
| `MIN_CANVAS_WIDTH` | 480 | 小流程最小画布宽度 |
| `MIN_CANVAS_HEIGHT` | 240 | 小流程最小画布高度 |
| `LABEL_SAFE_BOTTOM` | 24 | 事件和网关下方标签安全区 |

计算规则：

```text
contentWidth  = contentMaxX - contentMinX
contentHeight = contentMaxY - contentMinY
canvasWidth   = max(MIN_CANVAS_WIDTH,  contentWidth  + 2 * CANVAS_PADDING_X)
canvasHeight  = max(MIN_CANVAS_HEIGHT, contentHeight + 2 * CANVAS_PADDING_Y)
shiftX        = floor((canvasWidth  - contentWidth)  / 2) - contentMinX
shiftY        = floor((canvasHeight - contentHeight) / 2) - contentMinY
```

把所有节点 bounds、边 bounds 和边的中间绝对 docker 同步平移 `shiftX/shiftY`。边的首末 docker 是相对节点偏移，**禁止平移**。最后把顶层画布设为：

```json
{
  "upperLeft": { "x": 0, "y": 0 },
  "lowerRight": { "x": "canvasWidth", "y": "canvasHeight" }
}
```

平移只改变整体位置，不得改变节点间距、主行对齐、边的正交关系或网关半像素端点规则。左右边距和上下边距允许因整数取整相差最多 1px。

### 初始化视口：全部节点可见

#### 目标定义

首次打开设计器并完成渲染后，所有节点必须完整落在可视区域内。缩放比例由流程内容尺寸和当前窗口尺寸共同决定，**不要求固定为 100%**。

模型画布和浏览器视口是两个不同层次：

- zip 中的 `defJson.bounds` 控制模型内容和画布范围。
- 设计器前端的 zoom/pan 控制用户首次看到的区域。
- 只优化 `defJson` 不能保证首次打开全部节点可见；必须在前端加载完成后执行 fit-to-model。

#### 缩放计算

设视口安全边距 `VIEWPORT_MARGIN=24`：

```text
fitScaleX = (viewportWidth  - 2 * VIEWPORT_MARGIN) / contentWidth
fitScaleY = (viewportHeight - 2 * VIEWPORT_MARGIN) / contentHeight
fitScale  = min(fitScaleX, fitScaleY)
```

不要把 `fitScale` 强制设为 `1`。长流程允许小于 100%，小流程也允许由平台决定是否放大；唯一硬性目标是全部节点可见。

#### Oryx 调用方式

优先复用设计器已有 View 插件：

```javascript
$timeout(function () {
    var viewPlugin =
        KISBPM.TOOLBAR.ACTIONS._getOryxViewPlugin($scope);
    viewPlugin.zoomFitToModel();
}, 100);
```

若当前平台没有 `KISBPM.TOOLBAR.ACTIONS` 包装层，直接复用等价的 `ORYX.Plugins.View` 实例调用 `zoomFitToModel()`。禁止用 `setAFixZoomLevel(1)` 替代，因为它只表示固定 100%，不能保证长流程全部可见。

#### 调用时机

必须同时满足以下条件后再适配：

1. 模型 JSON 已加载并完成节点渲染。
2. 设计器容器已显示，`clientWidth/clientHeight > 0`。
3. 左右属性栏、工具栏或弹窗布局已稳定。

首次适配可使用 `$timeout` 或连续两次 `requestAnimationFrame` 延后执行。窗口变化、侧栏展开收起或编辑器弹窗尺寸变化时，使用防抖再次执行 `zoomFitToModel()`。

#### 屏幕级验收

对每个节点取得最终屏幕矩形 `nodeRect`，并验证：

```text
nodeRect.left   >= viewport.left   + VIEWPORT_MARGIN
nodeRect.top    >= viewport.top    + VIEWPORT_MARGIN
nodeRect.right  <= viewport.right  - VIEWPORT_MARGIN
nodeRect.bottom <= viewport.bottom - VIEWPORT_MARGIN
```

验收结果必须满足：

- 节点总数 = 完整可见节点数。
- 不可见或被裁切节点数 = `0`。
- 缩放比例不作为通过或失败条件。

如果设计器前端不在任务范围内，将此项报告为 `NOT_TESTED_FRONTEND`，不得把 zip 层的画布居中误报为“首次打开全部节点可见”。

## 三、边的 dockers（正交路由与路由网格）

### 3.1 核心规则

- 每一段必须严格水平或垂直，不得产生斜线。
- 默认优先使用源/目标中心行列 `srcCx/tgtCx/srcCy/tgtCy`。
- 如果默认中心行列会造成边穿节点、边与边重合或非端点交叉，必须使用分配后的辅助路由槽 `trackX/trackY`。
- 辅助槽仍属于正交路由网格；不得为避免冲突而产生任意斜线。
- 只允许不同边在共同节点端点相接，不允许共享一段有长度的线。

### 3.2 docker 结构

- **首点** = 源节点中心**相对偏移** `{源w/2, 源h/2}`
- **末点** = 目标节点中心**相对偏移** `{目标w/2, 目标h/2}`
- **中间点** = **绝对坐标**（转折点）

辅助槽只改变中间绝对坐标，不得破坏首末相对偏移。

### 3.3 0.5 像素对齐

XORGateway（40×40，偶数尺寸）的中心点用 `{20.5, 20.5}`（+0.5 像素对齐，Oryx 渲染特性），其他节点用整数。

### 3.4 路由常量

| 常量 | 默认值 | 用途 |
|---|---:|---|
| `GAP_X` | 50 | 同行节点基础水平间距 |
| `DETOUR_MARGIN` | 60 | 绕行槽距全部节点边界的最小距离 |
| `DETOUR_TRACK_GAP` | 30 | 相邻水平绕行槽间距 |
| `PORT_CLEARANCE` | 12 | 独立出线槽距节点边界的净距 |
| `PORT_SLOT_GAP` | 16 | 同一节点多个出线槽之间的间距 |
| `EDGE_NODE_CLEARANCE` | 12 | 边与非端点节点的期望视觉净距 |
| `EPSILON` | 1 | 坐标比较和重合长度容差 |

### 3.5 正交路由分场景

```
情况1 - 同行正常流向（目标在右边、跨度<300）：
  → 若中心线未穿过其他节点，使用直线，无中间点

情况2 - 同行回退（dx<=0）、同行远距离（跨度>=300），或中心线穿过非端点节点：
  → U 形，绕到主行上方，2 个转折点
  → 用 GLOBAL_DETOUR_Y（主行顶部之上 DETOUR_MARGIN）
  → 水平区间重叠的绕行边必须分配不同 trackY

情况3 - 目标在下方（dy>0）：
  → L 形，转折点 = {srcCx, tgtCy}（先竖后横）

情况4 - 目标在上方（dy<0）、跨度<=1000：
  → L 形，转折点 = {tgtCx, srcCy}（先横后竖）

情况5 - 目标在上方（dy<0）、跨度>1000（超长边）：
  → Z 形，绕到全局最底部（GLOBAL_DETOUR_BOTTOM_Y），2 个转折点

情况6 - 默认路由与已有边冲突：
  → 为源端或目标端分配独立 trackX/trackY
  → 重新生成候选路径并复查边-节点、边-边冲突
```

### 3.6 网关连线顶点粘附（DI waypoint 硬约束）

流程配置/查看页按 BPMN DI 渲染，网关画成菱形：**网关端 waypoint 必须精确落在菱形四个顶点（= DI 矩形四边中点）**。落在矩形角或边框其它位置，会渲染成「连到边上」，流程配置页甚至直接断线。

各形状端点几何要求（ht_flow 原生导出包实证 59/59）：

| 端点形状 | DI waypoint 落点 |
|---|---|
| 网关（菱形） | 菱形顶点 = DI 矩形四边中点（主轴吸附） |
| 事件（圆） | 圆周上 |
| 任务（矩形） | 矩形边界上 |

vsdx-relayout 构造性保证（任何输入进变换必产出顶点粘附产物，位于 `src/layout/vsdx-relayout.mjs`）：

- **shapeExit**：DI 首末 waypoint 按形状几何投影——网关取轴向顶点（|dx|≥|dy| 取水平顶点，否则垂直顶点）、事件沿中心连线投到圆周、任务用 boundaryExit 投到矩形边界
- **vertexSnap**：vsdx 粘附点距菱形顶点 <3.5px 时吸附为精确顶点（保留 vsdx 视觉折点）
- **gwGuide**：defJson 折线网关端正交引导拐点——defJson 线从节点中心穿出，轴向出发才落在顶点上；斜向出发会穿菱形斜边，表现为「连到边上」
- 2 点直连边含网关端且未吸附顶点时，插入 L 化拐点保证网关端轴向穿顶点

配套**输入预检**：relayout 匹配后未匹配节点/边非零时打印「⚠️ 输入预检: 源 vsdx 疑似版本过旧」告警——兜底重路由的网关多出线易共线拥挤，应先向用户确认 vsdx 版本再重排。

### 为什么分上方/下方绕行
- **上方绕行**：主行节点多，绕下方会穿过主行节点 → 绕上方（通常无节点）
- **下方绕行**：超长边（下行→主行最右）绕上方会穿过下行节点 → 绕到全局底部

## 四、边与边避让（强制）

### 4.1 冲突判定

把每条边的完整路径还原为：

```text
源节点中心 → 中间 dockers → 目标节点中心
```

再拆成水平/垂直线段，两两检查：

- **共线重合**：两条水平线同 Y 或两条垂直线同 X，交集长度 `> EPSILON`，判定失败。
- **非端点交叉**：水平线与垂直线相交，交点不是两条边共同节点的端点，判定失败。
- **共同端点**：两条边可以在同一节点中心相接，但从该点延伸后不得继续共享线段。
- **重复路径**：源、目标和全部中间点相同，判定失败。

### 4.2 独立出线槽

当一个网关同时是上一条绕行边的目标、下一条绕行边的源，并且两条边位于同一侧时，不得让两条边继续共用该网关的中心列。保留进入边的中心列，为离开边分配侧向槽：

```text
trackX = srcCx + direction * (srcW / 2 + PORT_CLEARANCE + slotIndex * PORT_SLOT_GAP)
```

向右的边 `direction=1`，向左的边 `direction=-1`。典型路径为：

```text
源中心
  → {trackX, srcCy}
  → {trackX, detourY}
  → {tgtCx, detourY}
  → 目标中心
```

这段源中心到 `trackX` 的短水平线用于把离开边从共享中心列中分离。多个出线使用不同 `slotIndex`。

### 4.3 绕行槽分配

不要简单地让每条绕行边都占一个新的 Y。按水平投影区间分配槽：

1. 计算每条绕行边的 `[minX, maxX]`。
2. 区间重叠的边不得复用同一 `trackY`。
3. 区间不重叠的边可以复用同一 `trackY`，避免画布无限向上或向下扩张。
4. 同一节点的多条边即使水平区间不重叠，也必须检查端口槽是否重合。

### 4.4 确定性重路由顺序

发生冲突时按以下顺序重试，保证相同输入得到稳定坐标：

1. 分配下一个端口槽 `trackX/trackY`。
2. 分配下一个水平绕行槽。
3. 在上方和下方之间选择无冲突且总长度较短的一侧。
4. 仍失败时扩大相关节点间距并重新布局。

每次重试后必须重新执行全部硬性检查，禁止只修复当前冲突而引入新冲突。

## 五、标签与视觉净距

标签位置可能由平台渲染器二次计算，因此作为视觉警告而不是导入阻断条件：

- 分支名优先使用简短的“是/否”“通过/驳回”。
- 长网关名称允许换行；必要时为网关两侧增加动态间距。
- 标签不得明显覆盖节点、箭头或其他标签。
- 边与非端点节点的推荐净距为 `EDGE_NODE_CLEARANCE=12`。
- 出现标签碰撞但几何硬性检查通过时，在交付结果中明确提示人工复核。

## 六、常见问题

| 现象 | 根因 | 解法 |
|------|------|------|
| 节点全堆在左上角 | 系统**不自动重排布局**，完全信 JSON 坐标 | 必须生成时算好坐标 |
| 流程偏在画布一侧 | 画布只按节点或原始坐标计算，未包含绕行线并统一平移 | 生成全部路由后执行自适应画布居中 |
| 绕行线落在画布外 | 顶层 bounds 忽略了边的绝对 docker | 用节点与边的联合 bounds 计算内容范围 |
| 画布已居中但首次打开仍需滚动 | 前端没有执行 fit-to-model，或调用时容器尺寸尚未稳定 | 模型渲染后调用 `zoomFitToModel()` 并做屏幕级验收 |
| 固定 100% 后长流程显示不全 | 把“全部节点可见”误解为“缩放等于 100%” | 移除固定缩放，按视口和内容自动计算比例 |
| 连线乱 | dockers 中间点用错（用了 layout 的 waypoint，尺寸不匹配） | 自己实现正交路由 |
| 节点重叠 | layout 按 100×80 布局，改成 100×46 后长名加宽超出预留空间 | 坐标重排（relayoutNodes） |
| 主行不齐 | 不同类型节点高度不同（30/28/46/40），layout 按顶边对齐 | 强制按中心 y 对齐 |
| 线穿过节点 | 长跨度横线 y 落在主行/下行节点位置 | 绕行到流程外围（上方/下方） |
| 水平绕行线重叠 | 水平投影区间重叠却复用了同一 trackY | 用区间分槽分配不同 trackY |
| 共享网关处竖线重合 | 进入边和离开边都使用网关中心列 | 为离开边分配独立 trackX 出线槽 |
| 两条正交边出现十字交叉 | 只检查边穿节点，未检查边与边 | 检测非共同端点交叉并确定性重路由 |
| 网关连线「连到边上」/配置页断线 | DI waypoint 落在菱形斜边或矩形角，而非顶点 | shapeExit 轴向投影 + vertexSnap + gwGuide（见 §3.6） |
| 网关多条出线挤在一起 | 源 vsdx 版本过旧缺该网关，兜底路由多边共线 | 输入预检告警后向用户索取最新 vsdx 重排；产物校验「出线分散」兜底 |
| 「是/否」覆盖网关名称 | 标签过长或网关两侧间距不足 | 缩短分支名、网关名称换行或增加动态间距 |

## 七、最终 ZIP 与视口验收

必须从最终 zip 内的 `bpmdefs.flow.xml` 重新解析 `defJson` 与 `bpmnXml`。禁止只检查输入 JSON、`bpmn-auto-layout` 输出或生成器内存对象。

### 7.1 硬性检查

- 节点尺寸符合标准：全部通过。
- 节点重叠：`0`。
- 主行节点中心 Y：一致。
- 所有节点、边路由和标签安全区：均位于画布 bounds 内。
- 内容左右边距差、上下边距差：均不超过 `1px`。
- 画布宽高：随内容增长，且不小于 `480×240`。
- 每条边：全部线段严格水平或垂直。
- 网关首末 docker：`20.5, 20.5`。
- DI 网关端点菱形顶点粘附：N/N（`verify-import` 检查项，见 §3.6）。
- 网关出线分散：同网关多出线不得同顶点同方向且共线重叠 `>60px`（短共享干道垂直分叉的 Y 形分支不算）。
- 边穿过非端点节点：`0`。
- 不同边共线重合长度 `> EPSILON`：`0`。
- 除共同节点端点外的边交叉：`0`。
- `defJson` 边 `resourceId` 与 `bpmnXml sequenceFlow.id`：集合完全相等。

任一硬性检查失败时，禁止交付 zip；重新分槽、重路由或扩大节点间距后再次生成。

### 7.2 初始化视口检查（需设计器前端）

- 模型首次打开且布局稳定后调用 `zoomFitToModel()`。
- 节点总数与完整可见节点数相等。
- 不可见或被视口裁切的节点：`0`。
- 不检查缩放百分比是否为 100%。
- 前端不在范围内时记录 `initial_viewport_fit=NOT_TESTED_FRONTEND`，不能记录为 PASS。

### 7.3 视觉警告

- 标签覆盖节点、箭头或其他标签。
- 绕行槽过多导致画布纵向过高。
- 流程过宽导致系统自动缩放后文字难以辨认。
- 边与非端点节点净距小于推荐值。

视觉警告不一定阻止导入，但必须在交付说明中列出。

## 八、回归用例

布局算法或规则变更后至少验证以下拓扑：

1. **纯线性流程**：所有节点同行，全部边为短直线。
2. **连续网关跳过边**：网关 A 跳到网关 B，网关 B 再跳到后续任务；验证共享网关处进入/离开竖线不重合。
3. **单网关多分支**：同一网关有两条以上绕行边；验证端口槽和水平槽均独立。
4. **合流后立即分流**：同一网关同时存在多条入边和出边；验证只共享节点端点。
5. **同行回退环**：验证上方 U 形绕行和多槽分配。
6. **多行超长回主行**：验证底部 Z 形绕行不穿过其他行节点。
7. **长中文节点名和网关名**：验证节点不重叠，并记录标签视觉警告。
8. **负坐标绕行边**：验证自适应平移后所有内容进入画布，且上下左右边距对称。
9. **极小与超宽流程**：验证最小画布限制和大流程按内容自动扩展。
10. **不同视口尺寸初始化**：分别用宽屏、窄屏和弹窗尺寸打开同一流程，验证所有节点完整可见且缩放比例允许不同。

所有回归用例必须满足：节点重叠、边穿节点、边边重合和非端点交叉均为 `0`。
