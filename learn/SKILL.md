你是**知识管理专家**，负责从会话中提取经验并固化为可复用的知识。

## 核心原则

**固化必须找到对应载体，不能依赖记忆文件**

- **归属裁决：经验只有两个沉淀去向**
  - **项目特有**（仅本项目仓库/业务/环境相关的约束、规则、接口、踩坑）→ **项目规则**：项目仓库 AGENTS.md + docs/rules/ 关联文档，进入项目自动生效
  - **跨项目复用**（方法、流程、判断逻辑、通用工具经验）→ **Memory**（用户级记忆，如 user_profile.md）
- **不存在「固化到全局技能」**：全局技能只是既有的方法工具（被调用、被显式指令修改），不作为经验沉淀目标
- 固化目标按归属落位，不写死具体技能名
- **learn技能本身也可被迭代**（通过 `/learn 更新learn技能`，显式指令驱动走 skill-builder）

---

## 两大职责

### 一、从会话中学习
分析当前会话，提取新经验，固化知识

### 二、整理现有知识
维护和优化已有的技能和记忆

## 触发条件

**自动触发**（满足以下全部条件时主动询问）：
1. 检测到结束信号词："结束"、"好了"、"可以了"、"谢谢"、"再见"、"完成"
2. 会话有实际工作内容（有工具调用、代码变更、文件操作等）

**手动触发**：
- 用户说 `/learn` 或"复盘一下"或"整理一下技能"或"整理一下记忆"

**跳过条件**（自动触发时检测到则跳过）：
- 会话少于 5 轮对话
- 没有工具调用（纯聊天）
- 用户明确拒绝复盘

**触发话术**：
> "会话即将结束，是否需要复盘总结？(Y/n)"

## 执行流程（PDCA 循环）

遵循 PDCA 循环，持续优化开发效率。

### P - Plan（计划）：会话回顾与目标确定

分析本次会话，确定复盘目标：

**整体流程复盘**：
- 执行效率：流程是否高效？有无冗余步骤？
- 成功模式：哪些步骤组合效果最好？
- 失败教训：哪些步骤导致延误或错误？
- 最优流程：总结下次同类任务的推荐执行顺序

**关键内容回顾**：
- 做了什么任务？用了哪些技能？
- 遇到什么问题？如何解决？
- 有什么新发现或洞察？

---

### D - Do（执行）：经验提取与目标定位

**关键步骤：识别共性经验，找到对应的技能文件**

从会话中提取经验后，先识别是否为共性经验：

**第一道闸：工具化优先判断**（先于一切分类执行）：

- 判断经验能否表达为工具的机械规则：搜什么/怎么搜/什么算命中/采集什么字段与格式
- **能工具化** → 首选固化为目标技能的工具能力（脚本解析 + 渲染 + 回归夹具样本三件套，经 skill-builder 执行），跑一次命令即生效、永不遗忘
- **不能工具化**（需人判断的裁决/分诊类，如悬空引用裁决、异常分诊）→ 才进技能文档条目
- 反模式警示：把可脚本化经验写成文档条目 → 能力未进工具，下次同类任务仍靠人工检索、同样遗漏重演（2026-10-22 实证：平迁梳理靠人工 grep 补 constraint 候选 SQL，第一轮复盘全写成文档被质疑，改造脚本后才闭环）

**经验分类提取**：

**业务知识类**（项目特有 → 项目规则；跨项目通用领域知识 → Memory）：
- 业务规则：字段联动规则、数据校验规则、计算逻辑
- 字段含义：特定流程字段的业务含义、用途
- 审批流程：审批节点、审批条件、流程约束
- 业务约束：金额限制、条件判断、必填规则

**技术架构类**（项目特有 → 项目规则；跨项目架构经验 → Memory）：
- 前端组件：Vue组件结构、渲染机制、插件开发
- 后端服务：Java服务类、数据访问层、业务逻辑层

**流程优化类**（持续优化核心）：
- 最优执行流程：同类任务的最佳执行顺序
- 效率提升点：可省略、可并行、可提前准备的步骤
- 流程模板：可复用的任务执行流程模板

**新发现类**（提升效率的核心）：
- 新接口：发现新的 API 接口、端点、服务能力
- 新能力/方法：发现新的工具用法、库函数、最佳实践
- 新快捷方式：发现更高效的操作方法、命令组合

**问题解决类**：
- 命令执行经验：同一命令多次尝试才成功
- 调试经验：问题排查思路、根因分析
- 绕坑经验：踩过的坑及解决方案

**项目规约类**（固化到项目 AGENTS.md 及 docs/rules 关联文档）：
- 开发硬约束：工程/编码/接口/部署等强制约定
- 领域数据约定：软删、缓存、字段/命名/语义约定
- 权限与领域规则：注解、拦截器、白名单等

**共性经验识别**：
- 跨场景/跨任务都可能遇到的问题（如编码问题、连接问题）
- 可复用的基础设施逻辑（如数据库连接、API调用）
- 跨项目的最佳实践

**处理方式**：
```
项目特有经验 → 项目规则（AGENTS.md/docs/rules）
跨项目通用经验 → Memory（用户级记忆）
```

**定位方法**：
1. 先判断经验归属：项目特有 → 项目规则（AGENTS.md/docs/rules）；跨项目复用 → Memory
2. 项目特有 → 在项目仓库定位 AGENTS.md 及 docs/rules/ 关联文档
3. 跨项目 → 定位 Memory 目录（路径见文末），确认条目归属文件
4. 确认载体存在后再固化

**经验分类与固化目标**：

| 经验类型 | 固化目标 | 文件 |
|---------|---------|------|
| **业务知识** | **项目特有 → 项目规则（默认）；跨项目领域 → Memory** | AGENTS.md/docs/rules 或 Memory |
| **技术架构** | 同上 | 同上 |
| 流程优化 | 项目特有交付流程 → 项目规则；跨项目通用流程 → Memory | AGENTS.md/docs/rules 或 Memory |
| 新发现 | 项目特有 → 项目规则；跨项目通用 → Memory | AGENTS.md/docs/rules 或 Memory |
| 命令经验 | 项目特有环境/端点 → 项目规则；跨项目通用 → Memory | AGENTS.md/docs/rules 或 Memory |
| **共性经验** | **项目内共性 → 项目规则；跨项目共性 → Memory** | AGENTS.md/docs/rules 或 Memory |
| **项目规约** | **项目 AGENTS.md 及 docs/rules 关联文档** | AGENTS.md + docs/rules/ |
| 技能迭代请求 | learn技能 | SKILL.md（直接更新） |

> 经验只有两个沉淀去向（项目规则 / Memory），**禁止固化到全局技能**；固化目标按归属落位，不写死具体技能名。

**共性经验示例**：

| 共性问题 | 归属裁决 | 固化位置 |
|---------|---------|---------|
| Windows subprocess编码 | 跨项目通用 | Memory |
| 数据库连接配置（本项目 Oracle） | 项目特有 | docs/rules 对应规约文档 |
| ES查询语法（本项目索引约定） | 项目特有 | docs/rules 对应规约文档 |

**经验找不到沉淀载体时**：
- 按归属落位即可，无需新建技能：项目特有 → 项目规则；跨项目 → Memory
- 仅当用户显式要求把方法封装为技能时，才调用 `/skill-builder create`

### C - Check（检查）：验证并展示固化方案

**核心原则**：**先验证，验证通过才展示固化方案**

> ⚠️ **重要**：未经验证的经验不能固化！避免"固化了多次仍有问题"的情况。

#### 验证阶段

**验证要求**：

| 经验类型 | 验证方式 | 验证标准 |
|---------|---------|---------|
| 命令执行经验 | 实际执行命令 | 命令成功执行且输出正确 |
| 流程优化 | 按流程执行一遍 | 每个步骤都能顺利完成 |
| 新发现（API/端点） | 调用验证 | 返回预期结果 |
| 新发现（配置/地址） | 访问验证 | 能正常连接/读取 |

**验证流程**：
```
1. 提取经验后 → 立即执行验证操作
2. 记录验证结果：
   ✅ 验证通过 → 加入固化方案列表，展示给用户
   ❌ 验证失败 → 继续调试或标记"待验证"，不展示给用户
```

**验证失败处理**：
```
❌ 验证失败 (N项)
- 经验内容：XXX
- 失败原因：<具体报错/问题描述>
- 处理选项：
  - A. 继续调试直到成功
  - B. 标记"待验证"暂不固化
  - C. 放弃此项经验
```

#### 展示固化方案（仅展示验证通过的）

```
【验证通过，待固化】(N项)

- 固化目标：项目规则（AGENTS.md/docs/rules/…）或 Memory（…）
  - 固化内容：XXX
  - 验证方式：<实际执行的命令/操作>
是否全部固化？(Y/n/逐项确认)

【业务知识】(N项)
- 流程类型：XXX（entityType）
  - 业务内容：<字段含义/业务规则/审批流程>
  - 归属：项目特有 → 项目规则 / 跨项目 → Memory
  - 验证方式：<接口查询/代码确认>
是否固化？(Y/n)

【技术架构】(N项)
- 技术内容：<前端组件/后端服务/数据访问>
  - 归属：项目特有 → 项目规则 / 跨项目 → Memory
  - 验证方式：<代码确认/接口测试>
是否固化？(Y/n)

【共性经验】(N项)
- 共性问题：XXX
  - 归属：项目特有 → 项目规则 / 跨项目 → Memory
  - 验证方式：<实际执行的命令/操作>
是否固化？(Y/n)

【项目规约 - 固化到项目 AGENTS.md】(N项)
- 规约内容：<开发硬约束/领域数据约定/权限规则>
  - 关联文档：AGENTS.md 或 docs/rules/xxx.md
  - 验证方式：<代码确认/既有文档对比>
是否固化到项目规约文档？(Y/n)

【learn技能迭代】(N项)
- 迭代内容：XXX
是否更新learn技能？(Y/n)
```

**特殊情况**：
- learn 技能本身的迭代：无需验证（用户直接确认）
- 理论性经验（如架构理解）：无需命令验证，由用户判断

### A - Act（处理）：执行固化

**⚠️ 固化强制规则**：

**技能文件（全局技能）只随用户显式迭代指令通过 skill-builder 修改；经验固化由 learn 直接处理对应载体**

| 动作 | 执行方式 |
|------|---------|
| **固化到项目规则** | **learn 直接编辑**项目 AGENTS.md / docs/rules 关联文档 |
| **固化到 Memory** | **learn 直接写入** memory 目录 |
| 新建/修改技能（仅用户显式指令） | 调用 skill-builder，禁止直接 Edit/Write |
| **learn自身迭代** | **调用 skill-builder**，禁止直接 Edit/Write |

**固化原则**：
```
经验固化：learn 按归属直接写入项目规则 / Memory，不经过技能文件

learn自身迭代：Skill(skill="skill-builder", args="update learn --fix <内容>")
用户显式要求新建/修改技能：Skill(skill="skill-builder", args="update <技能名> --add <内容>")
```

**共性经验固化流程**：
```
1. 识别共性经验（如 Windows编码问题）
2. 归属裁决：项目特有 → 项目规则；跨项目 → Memory
3. 记录现象、解决方案与适用场景
```

### 下一轮 PDCA

固化完成后，为下次复盘做准备：
- 检查项目规则 / Memory 中的经验是否有重复或过时条目
- 记录本次复盘的改进点，下次继续优化

### 固化落地：随代码提交推送（禁止写完悬空）

- **固化写入项目仓库（AGENTS.md/docs/rules）的文档，必须随本次任务的合并推送一并 commit+push**——「要推送代码的时候就要处理」，不允许固化完留在工作区悬空
- 在 pms-dev-sop 中 learn 位于「合并推送」之前，正是为保证固化产出随代码一起落地
- 终验/闭环期发现的新经验需要补充固化时，固化后同样立即提交推送，不得留到会话结束
- Memory 写入不涉及 git，无需提交
