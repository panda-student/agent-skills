# 测试产物归档整合规范

## 一、适用范围

描述迭代工作区测试产物归档到产品知识图谱时的整合格式与合并规则。涵盖两类产物：

1. **测试用例**（`测试用例/` 下的 `.md` 文件）
2. **自动化覆盖清单**（`api_{project}_coverage.md`）

---

## 二、测试用例整合

### 2.1 迭代区源文件格式

迭代区的测试用例遵循 [Markdown 测试用例模板](markdown-testcase-template.md) 的层级格式，只有两种形态：

**形态A：一个迭代一份聚合文件**
```
测试用例/
└── {迭代名称}_测试用例_{date}.md    （内含多个功能模块的用例，## 标题为模块名，### 标题为场景名）
```

**形态B：按模块拆分的多份文件**
```
测试用例/
├── 短信回调-测试用例.md     （含 TC-001、TC-002）
└── 用户管理-测试用例.md     （含 TC-003）
```

用例内容格式统一为：

```
## {模块名称}
### {场景名称}
#### [P{优先级}] TC-{序号} {用例标题}
- 前置条件：{内容}
  - 测试步骤：{内容}
    - 预期结果：{内容}
```

### 2.2 模块提取规则

模块识别方式取决于文件形态：

**形态A（聚合文件）**：从文件内容提取。`##` 标题为模块名，`###` 标题为场景名。用例归属的模块名取其上方最近的 `##` 标题。若用例上方无 `##` 标题 → 归入"未分类"。

**形态B（按模块文件）**：从文件名提取。文件名前缀（`{模块名}-测试用例.md` 或 `{模块名}模块-测试用例.md`）即为模块名。文件内部按 `##` / `###` / `####` 层级解析用例。

若以上方式均无法确定 → 归入"未分类"。

### 2.3 TC 编号提取规则

- 从 `#### [P{优先级}] TC-{序号} {用例标题}` 中提取 `TC-{序号}` 作为唯一标识
- 若标题无 TC 编号，尝试从文件名提取
- 若均无法提取，生成 `TC-AUTO-{序号}` 作为临时编号并提示用户

### 2.4 目标文件格式（模块文件）

每个模块最终在知识图谱中合并为一个文件：

```
ai_workspace/02.产品知识图谱/4.测试/测试用例/{模块名}-测试用例.md
```

### 2.5 模块文件模板

知识图谱中的模块文件遵循 [Markdown 测试用例模板](markdown-testcase-template.md) 层级格式，并追加归档元信息：

```markdown
# {模块名} - 测试用例

## 基本信息

| 字段 | 值 |
|------|------|
| 所属模块 | {模块名} |
| 用例总数 | N |
| 最后更新 | YYYY-MM-DD |
| 来源迭代 | {迭代名-1}, {迭代名-2}, ... |

---

## {场景名称}

#### [P{优先级}] TC-{序号} {用例标题}

- 前置条件：{前置条件内容}
  - 测试步骤：{测试步骤内容}
    - 预期结果：{预期结果内容}

> 来源迭代：{迭代名}

---

#### [P{优先级}] TC-{序号} {用例标题}

- 前置条件：{前置条件内容}
  - 测试步骤：{测试步骤内容}
    - 预期结果：{预期结果内容}

> 来源迭代：{迭代名}

---

## {场景名称2}
...
```

若无场景归属（旧格式迁移），统一归入 `## 未分类场景`。

### 2.6 合并规则

1. **同模块名已存在**：逐条对比迭代区用例与知识图谱中该模块的已有用例：
   - TC 编号（如 `TC-001`）**匹配** → **替换**该条旧用例，`来源迭代` 更新为当前迭代名
   - TC 编号**无匹配** → **追加**为新用例，`来源迭代` 记为当前迭代名，归入对应 `## {场景名称}` 下（无场景则归入 `## 未分类场景`）
   - 知识图谱中**有、迭代区没有的用例** → **保留不动**，`来源迭代` 不变
2. **新模块名**：**新建** `{模块名}-测试用例.md`，按场景分组写入，每条用例的 `来源迭代` 均记为当前迭代名
3. **模块级来源迭代**：合并后更新基本信息中的来源迭代为当前迭代名

### 2.7 模块文件过大处理

若单个模块合并后用例数超过 **50** 条，提示用户是否按子模块拆分，格式为 `{模块名}-{子模块}-测试用例.md`。

## 三、自动化覆盖清单整合

### 3.1 源文件格式

迭代区清单：`{迭代目录}/4.测试/自动化测试/API/api_{project}_coverage.md`（或 `自动化测试覆盖清单/API/`）

知识图谱清单：`ai_workspace/02.项目知识图谱/4.测试/自动化覆盖清单/API自动化/api_{project}_coverage.md`

格式遵循 [coverage-template.md](coverage-template.md)。

### 3.2 合并规则

按 `功能模块 + 关联接口` 匹配：

| 匹配结果 | 处理方式 |
|----------|----------|
| 知识图谱中已有匹配记录 | 更新该行：保留原创建时间、功能模块、关联接口、用例脚本路径同步为迭代区最新值、操作类型改为“修改” |
| 知识图谱中无匹配记录 | 在表格末尾追加新行，操作类型为“新增” |

### 3.3 基本信息更新

- `最后更新` → 当前日期
- `累计覆盖接口数` → 重新统计表格行数

### 3.4 新建清单

若知识图谱中不存在该 project 的清单文件，直接按[模板格式](coverage-template.md)新建。
