## 增量验证（L2）

使用 [rules-engine.md](rules-engine.md) 中的 **L2 标准规则** 进行增量验证。**核心原则：仅验证变更范围和关联章节，不执行全量验证。**

### 变更范围判定

变更范围与 L2 规则的对应关系详见 [rules-engine.md「增量验证规则」](rules-engine.md#增量验证规则)。此处仅汇总判定结论：

| 操作类型 | 验证范围 |
|---------|---------|
| 新建 PRD | 全文档（唯一执行全量 L2 的场景） |
| 新增/修改功能点 | 该 4.x 节 + 关联章节（3.3 功能清单、4.x 索引、跨模块引用） |
| 新增模块 | 新模块所有章节 + 3.3 节 + YAML `modules` |
| 修改产品概述 | 第 2 章 + 第 7 章验收标准（如目标变更） |
| 修改非功能需求 | 第 5 章 + 第 7 章指标验收 |
| 修改验收标准 | 第 7 章 + 关联功能点的 4.x 节 |
| 仅格式/措辞修正 | 仅涉及的行（L1 已在生成时覆盖） |
| 当前文档调优 | 变更功能点所在章节 + 关联章节 |

### 增量验证输出格式

```
📋 增量验证报告（L2）

验证范围：4.1 节（新增功能点 F-SYS-004）
关联章节：3.3 节功能清单、4.x 功能点索引

执行规则：
  R2.3 功能清单一致性  ✅ 通过
  R2.4 功能详情要素    ⚠️ 发现 1 个问题
  R2.6 模糊词检查      ✅ 通过

问题列表：
  #1 [High] F-SYS-004 缺少异常处理说明 → 进入修复
```

## 增量修复

修复优先级、修复动作映射、不可自动修复的问题判定均见 [rules-engine.md「修复机制」](rules-engine.md#修复机制)。**核心原则：修复一项，仅重验该项的影响范围，不重跑全量验证。**

### 修复执行流程

按 [rules-engine.md](rules-engine.md#增量修复流程) 定义的增量修复流程执行（单问题最多重试次数以 rules-engine.md 为准），仍失败则标记"需人工介入"。

### 修复报告格式

```
🔧 增量修复报告

修复统计：
  自动修复成功：3 项
  需人工介入：1 项

已修复：
  ✅ [High] F-SYS-004 补充了异常处理说明
  ✅ [Medium] 第 5 章响应时间从"较快"量化为"≤500ms"
  ✅ [Low] 第 3.3 节表格对齐格式修正

需人工介入：
  ⚠️ [Critical] "第三方短信服务商的 SLA 等级"需要与商务确认
     → 已在第 8 章依赖中标注"待确认"
```
